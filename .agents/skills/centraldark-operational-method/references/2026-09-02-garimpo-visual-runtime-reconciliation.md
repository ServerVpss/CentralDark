## 9. Casa vs VPS — quem prova o quê

Não existe um único runtime que possa provar tudo.

```text
CLAIM_IS_LOCAL_WINDOWS_DESKTOP
→ CASA_WINDOWS_PROVES

CLAIM_IS_SCREENPIPE_LOCAL
→ CASA_WINDOWS_PROVES

CLAIM_IS_LOCAL_CODE_CONNECT
→ CASA_WINDOWS_PROVES

CLAIM_IS_VPS_SERVICE_DEPLOYED
→ VPS_PROVES

CLAIM_IS_PUBLIC_ENDPOINT
→ VPS/EXTERNAL_PROBE_PROVES

CLAIM_IS_GITHUB_CODE_OR_HEAD
→ GITHUB_PROVES
```

O PC do CHEFE **não precisa ficar ligado** para manter verde de serviço que pertence à VPS. Depois de deploy provado, a VPS pode sustentar o runtime/health correspondente.

Mas:

```text
VPS_CANNOT_PROVE_LOCAL_DESKTOP=true
VPS_CANNOT_PROVE_LOCAL_SCREENPIPE=true
VPS_CANNOT_PROVE_LOCAL_FAVORITES=true
```

Ponte correta entre código e runtime:

```text
GITHUB_HEAD
→ BUILD/ARTIFACT_ID_OR_HASH
→ DEPLOY_TARGET
→ RUNTIME_RECEIPT
→ T1_REMEASURE
```
