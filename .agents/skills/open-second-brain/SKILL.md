# Open Second Brain

Use this skill when a user asks an agent to use, configure, inspect, or maintain Open Second Brain.

## Layout
Open Second Brain owns one top-level directory in the vault: `Brain/`. Everything the agent writes lives under it.

- `Brain/` — agent-writable observing memory. Taste signals, accreted preferences (unconfirmed → confirmed → retired), evidence log, snapshots. Operations: `brain_feedback`, `brain_apply_evidence`, `brain_dream`, `brain_brief`, `brain_query`, `brain_doctor` — see `brain-memory` skill. CLI: `o2b brain *`.
- User-authored notes — operator's daily journal, weekly notes, project notes. Folder names operator-chosen. Agent reads only when under `notes.read_paths` in `Brain/_brain.yaml`; never writes to them.

## Core principles
- Treat vault as user-owned durable knowledge.
- Write only into `Brain/`. Never write to user-authored note folders.
- Keep raw operational evidence separate from synthesized knowledge: per-event records in `Brain/log/`, preferences in `Brain/preferences/`.
- Never write secrets, tokens, passwords, private keys, or credential-bearing strings.
- Prefer deterministic CLI (`o2b brain ...`, `o2b doctor`, `o2b status`) over guessing paths.

## Default workflow
1. Check if OSB configured: `o2b status` or `second_brain_status` MCP tool.
2. Read machine-local config if available (vault path, agent identity, timezone).
3. Read vault-local manual `Brain/_BRAIN.md` (per-vault contract for agents).
4. Record taste signals via `brain_feedback` (see `brain-memory` skill).
5. After durable artifact, check applicable preferences and record evidence via `brain_apply_evidence`.
6. For read access to vault pages by title, use `second_brain_query`.

## Search surfaces
Name the surface a question is shaped for, route explicitly:
- Generic recall → `brain_search` (hybrid keyword + semantic over raw chunks).
- Summary surface → for specific source/artifact kind, search by source or filter by artifact kind (`source:<path>` or `kind:<type>`/`type:<type>`). `brain_search` detects structurally and returns `surface: "summary"` as advisory route hint.

## Safety
If write might affect outside `Brain/`, ask for explicit confirmation. When in doubt, prefer `Brain/`.
