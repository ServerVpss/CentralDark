======================================================================
FASE 4 — DESENHO DO FALLBACK LOCAL GRATUITO
======================================================================

OBJETIVO

Usar o máximo de providers/modelos gratuitos ou já incluídos nas assinaturas do
Pivete, sem aleatoriedade cega e sem quebrar contexto.

REGRAS

1. TAREFA LONGA / SESSÃO COM CONTEXTO
   - usar STICKY PRIMARY;
   - manter o modelo saudável durante a tarefa;
   - trocar somente por erro elegível;
   - ao trocar, transportar resumo, estado, ferramentas e restrições;
   - registrar por que trocou.

2. TAREFA CURTA / SEM ESTADO
   - pode usar rotação ponderada entre modelos gratuitos saudáveis;
   - respeitar cooldown e rate limit;
   - não oscilar a cada token;
   - não repetir provider que acabou de falhar.

3. ERROS ELEGÍVEIS PARA FALLBACK
   - 429;
   - timeout;
   - 5xx;
   - provider indisponível;
   - modelo indisponível;
   - capability ausente antes da execução.

4. ERROS NÃO ELEGÍVEIS PARA FALLBACK CEGO
   - prompt inválido;
   - permissão negada;
   - tool/write perigoso;
   - credencial inválida;
   - violação de política;
   - erro de caminho local causado pelo agente.

5. FAIL-CLOSED
   Para filesystem write, Git write, shell destrutivo, secrets, SQL write,
   deploy, restart ou administração:
   - não mudar para modelo menos capaz automaticamente;
   - bloquear e pedir Pivete quando a cadeia não satisfizer capability + segurança.

6. FAIL-OPEN CONTROLADO
   Somente para texto de baixo risco:
   - resumo;
   - classificação;
   - conversa curta;
   - extração;
   - documentação.

7. CIRCUIT BREAKER
   - 429 repetido: cooldown;
   - 5xx repetido: abrir circuito;
   - timeout repetido: rebaixar saúde;
   - teste periódico de recuperação;
   - sem loop infinito.

8. ORÇAMENTO
   - prioridade máxima para custo zero;
   - provider pago não pode entrar automaticamente nesta missão;
   - assinatura já paga pode ser tratada como INCLUDED, após prova;
   - registrar PAID_FALLBACK_DISABLED=SIM.

9. CAPABILITY ROUTING
   - texto;
   - visão;
   - tool use;
   - contexto grande;
   - código;
   - raciocínio;
   - latência.

Uma rota só recebe modelo que passou no capability test correspondente.

ARTEFATO

Preferir configuração/fallback nativo do Hermes.

Somente criar um adaptador local quando:

NATIVE_FALLBACK_SUPPORTED=NAO
e
GAP_PROVADO=SIM

Não criar segundo Gateway.
Não criar segundo Hermes.
Não duplicar config.

FASE 7 — CORREÇÃO DAS 3 TEMPERATURAS
======================================================================

OBJETIVO

Uma única árvore ATIVA e gravável.

Origem/espelho:
- preservada;
- somente leitura;
- não consumida como memória ativa concorrente.

Fluxo:

EVENTO / SESSÃO
        ↓
HOJE.md
        ↓ destilação idempotente
SEMANA.md
        ↓ promoção curada
REGRAS.md

REGRAS DE HOJE

- memória operacional recente;
- fatos em andamento;
- decisões ainda não consolidadas;
- evidência e timestamps;
- deduplicação por ID/hash;
- tamanho/idade controlados;
- não apagar item ainda necessário.

REGRAS DE SEMANA

- resumo destilado;
- padrões recorrentes;
- decisões relevantes;
- pendências;
- causa → correção → teste;
- sem copiar HOJE inteiro;
- deve sobreviver a reset;
- atualizar de forma idempotente.

REGRAS DE REGRAS

- somente conhecimento estável;
- regra aprovada;
- teste de reincidência;
- origem/proveniência;
- conflitos resolvidos;
- não promover conversa crua;
- não promover toda decisão automática.

AUTOMAÇÃO

Preferência:

1. hook oficial de fim de sessão, quando suportado;
2. scheduler/cron oficial do Hermes;
3. tarefa local segura e documentada;
4. script externo somente se não houver mecanismo nativo.

Cadência inicial candidata:

- destilar HOJE → SEMANA a cada 6 horas E no fechamento controlado da sessão;
- avaliar SEMANA → REGRAS uma vez por dia ou por threshold;
- promover para REGRAS somente quando passar critério de estabilidade.

A cadência final deve respeitar o manual original e o runtime.

Não criar dois schedulers para a mesma função.

PLANO 90%

O remendo “90% plano” não deve ser apagado de imediato.

Manter como FALLBACK_MANUAL até:

- automação rodar;
- três ciclos verdes;
- reset simulado verde;
- ausência de perda;
- ausência de duplicata.

Depois classificar:
90_PERCENT_PLAN=RETIRED|MANUAL_FALLBACK|ACTIVE
