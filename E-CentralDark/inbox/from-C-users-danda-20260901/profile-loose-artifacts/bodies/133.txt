## Objetivo

Consolidar `https://hub.centralldark.com/` como painel de conectores/contas/multicontas e `https://api.centralldark.com/` como rota única organizada para APIs, gateways, conectores, LLMs e fallback híbrido.

## Contexto

O HUB já existe e mostra área de conectores para:

- Grok/xAI;
- Claude;
- OpenAI;
- Gemini;
- Notion;
- GitHub;
- Google Drive;
- Supabase;
- gateways ativos como MCP Gateway, Telegram MTProto e Supabase HUB.

O objetivo é conectar várias contas por provedor em um só lugar, com OAuth/API Key controlado, auditoria, expiração, logs no Hermes e snapshot seguro para painéis.

## Evidência visual reportada

Na tela do HUB aparece erro:

```text
Could not find the table 'api.oauth_connections' in the schema cache
```

Isso indica provável falta de migration/schema/cache para a tabela `api.oauth_connections` ou desalinhamento entre frontend/backend/Supabase.

## Princípio de arquitetura

```text
hub.centralldark.com = painel/admin/conectores
api.centralldark.com = gateway/rota única de APIs
mcp.centralldark.com = tools/MCP
status.centralldark.com = observabilidade pública/sanitizada
mobile.centralldark.com = app/PWA de bolso
```

Evitar multiplicar subdomínios sem necessidade. Preferir módulos/rotas quando fizer sentido.

## Fallback híbrido de LLMs

Objetivo: se um provedor falhar, degradar para outro com registro/auditoria.

Fluxo:

```text
pedido
-> policy/router
-> provedor primário
-> se falhar: fallback 1
-> se falhar: fallback 2
-> registra uso/erro/latência
-> retorna resposta ou erro explicado
```

## Sobre proxies externos

Referências citadas:

- `xtekky/gpt4free`: avaliar apenas em sandbox/laboratório, nunca como rota crítica sem auditoria legal, segurança, estabilidade e termos de uso.
- `pedrofariasx/unlimited-ai-proxy`: avaliar como lab router OpenAI-compatible, com autenticação, rate limit, logs e isolamento antes de qualquer uso sensível.

## Travas

- Não pedir, expor ou salvar secrets em chat/frontend.
- OAuth tokens e API keys devem ficar server-side, cifrados ou em secret storage apropriado.
- Frontend só consome status/snapshot sanitizado.
- Nada de provider experimental em produção sem sandbox e avaliação.
- Toda rota precisa ter owner, risco, log e política.
- Ação sensível exige Manual Confirm.
