## 🩻 As 3 rotas que o Pivete perguntou

- `https://mcp.centralldark.com/admin` → painel admin em HTML esmeralda; responde 401 até o browser mandar Bearer admin. **Bug UX** (HTML + 401).
- `https://mcp.centralldark.com/mcp` → endpoint MCP público JSON-RPC Streamable HTTP; exige OAuth scope `mcp`. Funciona.
- `https://mcp.centralldark.com/admin/mcp` → endpoint MCP privilegiado JSON-RPC; exige OAuth scope `admin`. Funciona.

---

## 🔴 Falhas / atritos para o ChatGPT conectar

1. **Falta header `WWW-Authenticate: Bearer resource_metadata="..."`** em `/mcp` 401. É **obrigatório pelo spec MCP 2025-06-18** para o ChatGPT disparar o fluxo OAuth automaticamente. Hoje o cliente só vê `Bearer ausente` no body e não sabe onde autorizar.
2. **Sem `/sse`** — o conector antigo tenta SSE e cai. Melhor 410 Gone explícito que 404 JSON.
3. **`/admin` devolve HTML com HTTP 401** — clientes MCP genéricos veem "unauthorized" e não descobrem UI.
4. **Sem `/favicon.ico`** — ícone genérico na lista do ChatGPT.
5. **OpenAPI anuncia `/mcp-tools/<name>`** mas servidor só serve via `/mcp` JSON-RPC. Cliente OpenAI-compat literal bate 404.
6. **Sem `/.well-known/ai-plugin.json`** — ChatGPT antigo (Plugins/Custom GPT) não descobre.
7. `/token` e `/register` GET respondem JSON 404 `not_found` (POST funciona). Aceitável, mas gera ruído.

---

## 🛠️ Correções sugeridas (ordem de impacto)

1. **Adicionar** `WWW-Authenticate: Bearer resource_metadata="https://mcp.centralldark.com/.well-known/oauth-protected-resource"` em toda 401 de `/mcp` e `/admin/mcp`.
2. Servir `/favicon.ico` (32x32 esmeralda).
3. Padronizar `/admin` (200 SPA login OU 401 minimalista).
4. Adicionar `/sse` → 410 Gone com body explicando "use /mcp Streamable HTTP".
5. Sincronizar OpenAPI: remover `/mcp-tools/*` OU implementar as rotas HTTP diretas.

## 🧾 Como o ChatGPT deve conectar (fluxo comprovado)

```
1. GET  /.well-known/oauth-protected-resource
2. GET  /.well-known/oauth-authorization-server
3. POST /register   (DCR aberto → retorna client_id)
4. GET  /authorize?response_type=code&client_id=<x>&redirect_uri=<cb>&code_challenge=<s256>&code_challenge_method=S256&scope=mcp&state=<s>
5. POST /token      (troca code por access_token)
6. POST /mcp   Authorization: Bearer <token>   {jsonrpc:"2.0", method:"initialize", ...}
```

Todos os 6 passos foram executados e responderam corretamente na varredura.
