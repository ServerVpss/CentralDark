Persistência de sessão entre abas do WebUI

Se você abrir múltiplas abas do Hermes WebUI (como http://127.0.0.1:9119/ e http://localhost:8648/) usando o mesmo perfil (pivete), elas compartilham a mesma configuração, skills e memória de longo prazo (como o Card-Mestre e as três temperaturas), mas cada aba inicia uma sessão de chat separada por padrão, a menos que você recupere explicitamente o mesmo ID de sessão.

Para manter o histórico de conversa contínuo entre abas, você tem três opções:

  1. Use uma aba apenas (a abordagem mais simples e recomendada para evitar confusão)
  2. Transfira manualmente o ID da sessão:
    • Na primeira aba, execute /status no chat ou hermes sessions list no terminal para obter o ID da sessão ativa
    • Na segunda aba, antes de enviar qualquer mensagem, recupere essa sessão via:
      • Clique no ícone de perfil → "Resume session" → cole o ID
      • Ou, se o frontend suportar, adicione ?session=SEU_ID_AQUI à URL
  3. Aguarde recursos futuros que possam expor o session_id na URL por padrão (atualmente em discussão no repositório oficial)
Importante: Alterações feitas em uma aba (como carregar uma skill com /skill nome ou mudar configurações com hermes config set) são visíveis em todas as abas imediatamente, pois elas leem os mesmos arquivos em disco. Apenas o histórico de conversa (mensagens trocadas) é isolado por sessão.

Tradutor na VPS faz ferramentas gastarem saldo Lovable sem saberem. Funciona. Ninguém de fora consegue falar com ele — nem você aqui de casa.

O que ele faz, em uma linha

No código está escrito server.listen(PORT, '127.0.0.1'). Esse 127.0.0.1 significa “só aceito quem já está dentro desta máquina”. O domínio lovable.centralldark.com responde 200, mas com corpo vazio e cabeçalho do Cloudflare — é a nuvem respondendo, não o bridge. Testado nas quatro rotas: todas vazias.

Resolvido: a chave viva do pivete foi copiada pro sol. Ela estava escrita duas vezes no arquivo — as duas foram trocadas. Os dois perfis agora dividem a mesma conta.

Você mandou uma foto e o bot ficou seis minutos calado. Não deu erro, não deu aviso — silêncio. A explicação: o modelo principal do sol era o tencent/hy3, que só lê texto. Quando a foto chegava, o sistema tentava mesmo assim, batia num “não sei ler imagem” e a conversa morria ali.
