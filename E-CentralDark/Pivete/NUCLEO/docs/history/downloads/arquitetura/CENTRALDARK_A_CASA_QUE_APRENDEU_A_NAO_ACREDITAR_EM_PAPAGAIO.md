# CENTRALDARK — A CASA QUE APRENDEU A NÃO ACREDITAR EM PAPAGAIO

## Natureza do artefato

Este pacote documenta o pôster visual da CENTRALDARK como **interface narrativa/cognitiva**.

> IMAGE != DOCUMENTATION  
> DOCUMENTATION != DIAGRAM  
> VISUAL_CLAIM != RUNTIME_PROOF  
> REALITY = JUDGE

A imagem representa uma Casa que evolui do caos para um método operacional: observar, errar, provar, aprender, contar e continuar.

## Mensagem central

**Não é sorte. É método. É trajetória.**

A CENTRALDARK não deve confiar em repetição, aparência de sucesso ou narrativa de agente.  
O sistema deve transformar experiência em evidência, evidência em aprendizado e aprendizado em comportamento futuro melhor.

## Elementos visuais principais

### 1. CENTRALDARK / A CASA

A Casa aparece como o núcleo de continuidade.

Ela simboliza:

- uma única autoridade operacional;
- memória persistente;
- reconciliação;
- autonomia condicionada por prova;
- continuidade entre sessões;
- absorção de aprendizado no organismo existente.

Fluxo conceitual:

`CAOS → CASA → MÉTODO → PROVA → APRENDIZADO → CONTINUIDADE`

### 2. Papagaio

O papagaio representa:

- repetição sem entendimento;
- eco;
- ruído;
- resposta bonita sem causalidade;
- `PASS` sem prova.

Regra:

`REPETIÇÃO != COMPREENSÃO`

O pôster marca o papagaio como **NÃO ACREDITADO** até existir evidência.

### 3. Hermes

Hermes aparece como braço operacional.

Responsabilidade representada:

- executar;
- medir;
- testar;
- coletar evidência;
- devolver resultado;
- continuar o trabalho da Casa.

Hermes não é a autoridade final da verdade.

`HERMES = EXECUTOR/PRESERVAÇÃO`  
`REALITY = JUDGE`

### 4. Grafo / Memória

O painel de grafo representa memória associativa e conhecimento recuperável.

Conecta:

- fatos;
- decisões;
- provas;
- causas;
- relações;
- trajetórias.

O grafo não transforma relação em causa automaticamente.

`CONNECTION != CAUSE`

### 5. Triagem / Filtro

O funil visual representa o garimpo de informação.

Entrada:

- ruído;
- repetição;
- acréscimo;
- conteúdo bruto.

Saída desejada:

- evidência;
- contexto;
- coerência;
- trajetória útil.

Fluxo:

`MATERIAL BRUTO → TRIAGEM → CONTRAPROVA → DELTA ÚTIL → CRISTAL`

### 6. Trajetória / Narrativa

A camada narrativa organiza:

`EVENTOS → DREAM REVIEW → TRAJETÓRIA`

A narrativa é uma visão humana derivada.

Ela não substitui:

- receipts;
- logs;
- hashes;
- testes;
- estado vivo.

`HISTORY = PROVENIENCE`  
`CURRENT_STATE = MEASURED_NOW`

### 7. Estado / Sistema

O painel de status expressa o objetivo visual de maturidade operacional:

- estado vivo;
- autonomia;
- consistência;
- canonicidade;
- evidência.

Importante: números, porcentagens e estados apresentados no pôster são **elementos narrativos/visuais**. Não devem ser tratados como medição real de runtime sem prova externa correspondente.

## Ciclo cognitivo representado

1. **OBSERVAR** — medir o que existe.
2. **ERRAR** — tratar falha como sensor.
3. **PROVAR** — testar a hipótese e tentar quebrá-la.
4. **APRENDER** — transformar conclusão sobrevivente em mudança de comportamento.
5. **CONTAR** — gerar narrativa humana sem substituir evidência técnica.
6. **CONTINUAR** — iniciar o próximo ciclo do último estado bom comprovado.

## Invariantes

- `REALITY = JUDGE`
- `UNKNOWN != PASS`
- `ACTION != PROOF`
- `DOCUMENTED != EXECUTED`
- `HISTORY != CURRENT_STATE`
- `CORRELATION != CAUSE`
- `REUSE_BEFORE_CREATE`
- `ONE_SYSTEM_ONLY`
- `ONE_WRITER_PER_SCOPE`
- `LAST_GOOD_STATE → NEXT_EXECUTION_BASELINE`

## Arquitetura conceitual

```text
CHEFE / INTENÇÃO
      ↓
CENTRALDARK / CASA
      ↓
OBSERVAÇÃO + ESTADO VIVO
      ↓
HERMES / EXECUÇÃO
      ↓
EVIDÊNCIA
      ↓
CONTRAPROVA
      ↓
REALITY JUDGE
      ↓
APRENDIZADO
      ↓
MEMÓRIA / GRAFO
      ↓
TRAJETÓRIA / NARRATIVA
      ↓
NEXT BOOT
      ↺
```

## Critério de verdade

A imagem pode inspirar e orientar.

Ela não prova que:

- Hermes está vivo;
- autonomia foi alcançada;
- um processo está rodando;
- o sistema está em 100%;
- uma integração existe;
- um aprendizado foi incorporado.

Essas afirmações exigem prova da camada correspondente.

## BOOT

`OBSERVAR → ERRAR → PROVAR → APRENDER → CONTAR → CONTINUAR`

## Fio da missão

`visual → documentação → diagrama → pacote → continuidade`
