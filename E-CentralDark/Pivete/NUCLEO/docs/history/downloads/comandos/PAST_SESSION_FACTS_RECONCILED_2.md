
# Fatos recuperados de sessões anteriores e reconciliados

Fontes: histórico/biblioteca já materializados no pacote-base + repo canônico.

1. `#ACORDAR → !CALIBRAR → !MULTIBÚSSOLA → !META_LUPA → ...` já vinha sendo
   consolidado como ciclo de estado vivo, alinhamento, falsificação e remedição.
2. Regras recorrentes: `UNKNOWN != PASS`, `REALITY = JUDGE`, `ACTION != PROOF`,
   `DOCUMENTED != EXECUTED`, `HISTORY != CURRENT_STATE`.
3. `ONE_WRITER_PER_SCOPE`: percepção pode paralelizar; mutação deve serializar.
4. Houve histórico de correções humanas a agentes/modelos:
   - falso verde sem recibo;
   - CLI tratada indevidamente como botão desktop;
   - criação de `-v2` contra a regra de melhorar o existente;
   - autoria atribuída ao usuário sem origem real;
   - regra “menos é mais” aplicada indevidamente ao CHEFE.
5. Repo registra PAPAGAIO_MODE=OFF e aprendizado operacional.
6. `HUMAN_CORRECTION → SIGNATURE → INVARIANT → OWNER → TEST → GATE → CRYSTAL → NEXT_EVENT_REUSES`.
7. Reensino mecânico depois de promoção comprovada = `LEARNING_TRANSFER_FAIL`.
8. `fabler/fable-tutor` aparece em ledgers internos/históricos; isso não autoriza
   equiparar automaticamente esses nomes a uma instância atual de Claude Fable 5.
9. Fable real não foi executado 100 vezes nesta sessão; os 100 casos foram
   simulação/corpus adversarial.
10. O método operacional não depende de acesso à chain-of-thought bruta;
    comportamento observável, logs, estados, receipts, hashes e regressões são auditáveis.
