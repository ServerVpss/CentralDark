# CRISTALIZAÇÃO — PROJETO INTEIRO

Cristalização não é “criar uma skill para cada erro”.

```text
FAILURE
→ SIGNATURE
→ CAUSE
→ DISCRIMINATING TEST
→ MINIMAL REMEDIATION
→ RETEST
→ COUNTERPROOF
→ REUSABLE DELTA?
   NO → receipt/history only
   YES → choose existing owner
        → rule | test | skill | contract | memory | gate
        → prove consumer
        → prove future behavior changed
```

## Regra
`ERROR_IS_CRYSTALLIZABLE_CANDIDATE`, não `EVERY_ERROR_BECOMES_SKILL`.

A forma de cristal depende do owner causal. Se um teste/gate no código resolve melhor, criar skill seria entropia.

## Revisão contínua
Revisar skills/código por evento material (mudança, falha, stale, dependência, regressão), não por ritual diário sem ganho informacional.
