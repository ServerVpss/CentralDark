# Micro-Commit Packages on Main + Fixed Point Protocol (following user intention)

## Core Rule from User Intention
- Work in **micro-deltas** (1 small provable change per commit).
- When a **sufficient package** of related micros forms a logical unit advancing the requested/apointed fixed point → commit to main (or prepare batch) and continue.
- "Manda pra main e continua até o ponto fixo".
- Always respect: REUSE_BEFORE_CREATE, ONE_SYSTEM_ONLY, ONE_WRITER_PER_SCOPE, measure reality first (#ACORDAR), prove (you run it yourself), integrate to existing (PEGATUDO F4, elite-gateway, omni-router, SOUL).
- No bureaucracy: each micro must deliver visible artifact fast (file, output, commit, usable in model via CENTRAL DARK GATEWAY dropdown).
- "Ninguém bota no ar": prioritize commands that make the system usable *now*.

## "No Próximo Passo" Protocol
- User signals: "NAO TEM PROXIMO PASSO", "PROSIGA ATE O PONTO FIXO", "NAO TEM PROXIMO", "CONTINUA ATE TER O PONTO FIXO E ESTADO APROVADO E LIBERADO PARA USO", "/GOAL!"
- Action: **Do not offer next steps**. Execute, prove (run, show output, Screenpipe, git reality, HEAD), continue until fixed point criteria are met.
- Declare only when: "Ponto fixo atingido. Estado aprovado e liberado para uso."
- Pitfall: Offering "próximo passo" "atrapalha" the user.

## "Commit na Main Deixando Rastro Repetindo Tudo"
- When requested: commit directly on main with **long detailed message** that repeats the entire process (search, execution by you, proofs, integration, fixed point).
- The message itself is the "rastro" (trail) in git log.
- Example structure in message:
  - User request recap
  - What you searched alone
  - What you ran/used yourself
  - Single local output
  - Integration points (PEGATUDO, gateway_feed, dropdown)
  - Proofs (Screenpipe healthy, JSON validated, HEAD measured)
  - Fixed point declaration
  - Cross of VPS / local casa / GitHub remote / all docs

## Workflow for Micro Packages
1. #ACORDAR (measure git branch/HEAD, Screenpipe health, runtime, files).
2. Micro change + immediate proof (run the agent, cat the JSON, verify format, Screenpipe query).
3. Small commit with proof in message.
4. After 4-6 related micros (sufficient package for the delta):
   - Commit to main.
   - Continue to next micro toward the fixed point.
5. For the Zendrive class: the fixed point is "capture from open ZENDRIVE-CHAT GPT session (and provided URL) → 1 local output → integrated to CentralDark API (elite-gateway/omni-router) → usable in model by selecting CENTRAL DARK GATEWAY / Arsenal Router Med in Hermes dropdown".

## Full System Cross (VPS + Main Casa + GitHub Remoto + All Docs) — Always When Requested
Use this checklist and present in baianês + canonical emojis only:
- Git: current branch (often main or pr1408), HEAD vs origin/main, status, recent commits (the long rastro one).
- Local Casa (E:\CentralDark\Pivete\CentralDark): test-local zendrive files, Screenpipe :3030 (healthy), Hermes profile pivete.
- VPS: PM2 CentralDark-EliteHTTP (real gateway with zendriver, porta ~8082), status "online" in infra-vivo/graph-data.
- GitHub: ServerVpss/CentralDark, main as canonical, PRs (#1381 fixed-point, #1408 PEGATUDO etc.).
- Docs: SOUL-SOL (regras), AGENTS.md (boot + medir + git standard), BRAIN/GRAFO-VIVO (maps), TRIGGER-FABRIC (PEGATUDO cross-surface), status/*.json (EliteHTTP), ecosystem.config (PM2), MAPA-DE-ROTAS-VPS.
- Zendrive: mock (local simple functional) + real (VPS EliteHTTP). Output = gateway_feed for PEGATUDO F4. 1 local file. Usable via dropdown.
- Hermes: dropdown shows CENTRAL DARK GATEWAY / Arsenal Router Med = the way to "usar no modelo aqui".
- Fixed point signals: provado (rode você), aprovado (estado liberado), usável agora.

## Pitfalls
- Offering options or "próximo passo" when user wants continuous execution until fixed point.
- Long explanations instead of "execute first, report result".
- Creating new systems instead of extending elite-gateway + PEGATUDO + existing omni-router.
- Not proving with actual run output + Screenpipe + git reality.
- Losing the single local output (always use zendrive_*_capture.json as the released artifact).
