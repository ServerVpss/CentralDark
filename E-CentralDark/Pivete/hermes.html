Hermes Agent: o guia de referência para profissionais (2026)

# Um guia de referência para profissionais sobre o Hermes Agent, o agente de IA de código aberto e autoaperfeiçoável da Nous Research: autenticação de provedores e OAuth, arquivos de configuração, sistema de skills e execução como gateway de mensagens multiplataforma.

author: Blake Crosley words: 22651 read_time: 86m updated: 2026-07-22 07:01

Resumo: Hermes Agent é um agente de IA autoaperfeiçoável e de código aberto da Nous Research. Ele funciona como uma CLI e como um gateway de mensagens multiplataforma, armazena em disco uma identidade durável e uma memória persistente, agrega skills que melhoram com o uso e funciona com qualquer provedor de LLM compatível com OpenAI — Nous Portal, OpenRouter, Anthropic, GitHub Copilot, z.ai, Kimi, MiniMax, DeepSeek, Qwen Cloud, Hugging Face, Google, xAI/SuperGrok ou seu próprio endpoint auto-hospedado.1219 Desde a v0.14.0 (16 de maio de 2026), o Hermes oferece OAuth do SuperGrok com o contexto de 1 milhão de tokens do grok-4.3, um proxy local compatível com OpenAI para provedores de OAuth (hermes proxy), suporte nativo a x_search, instalação via PyPI (posteriormente descontinuada na v0.19.0 — o instalador de uma linha é o método compatível), instalação sob demanda de dependências, 22 plataformas de mensagens, incluindo LINE e SimpleX Chat, /handoff, diagnósticos semânticos de LSP após gravações, video_generate unificado, computer_use via cua-driver para provedores que não sejam Anthropic, versão beta nativa para Windows e a resolução de 12 itens P0 e 50 itens P1.19 A parte mais difícil para a maioria dos novos usuários é a autenticação do provedor: o Hermes oferece suporte nativo a cerca de 20 provedores, além de endpoints personalizados, e três caminhos distintos de autenticação (chave de API no .env, OAuth via hermes model ou endpoint personalizado no config.yaml). O modelo de autenticação é a primeira coisa que você deve aprender — todo o resto depende de qual provedor é resolvido.

O Hermes Agent funciona como um runtime completo de agente, não como uma simples camada de chat. Ele lê seu sistema de arquivos, executa comandos em backends isolados, extrai conteúdo da web, cria subagentes, executa tarefas cron agendadas, conversa pelo Telegram/Discord/Slack/WhatsApp/Signal/Email a partir de um único processo de gateway e cria as próprias skills com base na experiência.1 A CLI é uma interface de terminal construída sobre um loop de conversa em run_agent.py; o gateway é um processo de longa duração que encaminha mensagens das plataformas de mensagens pelo mesmo loop de conversa.3

A diferença entre o uso casual e avançado do Hermes se resume a cinco sistemas. Domine-os e o Hermes se tornará um multiplicador de produtividade:

  1. Resolução de provedores: como os fluxos de autenticação são convertidos em chamadas de API
  2. Hierarquia de configuração: config.yaml + .env + auth.json + SOUL.md + AGENTS.md
  3. Sistema de ferramentas + toolsets: o que o agente pode fazer, com permissões definidas por plataforma
  4. Sistema de skills: memória procedural que o agente cria e aprimora
  5. Gateway + cron + profiles: como executar o Hermes onde você está presente, não apenas onde você se encontra fisicamente

Principais conclusões

  • A autenticação do provedor tem três caminhos, não apenas um. Chave de API no .env, OAuth via hermes model/hermes auth ou endpoint personalizado no config.yaml. Escolha o caminho correspondente ao seu provedor, não aquele que simplesmente parece mais familiar.
  • Você pode trocar de provedor com um único comando. hermes model orienta você de forma interativa por todos os provedores compatíveis, incluindo logins por OAuth, e /model provider:model permite trocar durante uma sessão sem perder o histórico.2
  • Dois arquivos formam a superfície de configuração editável pelo usuário. ~/.hermes/config.yaml contém as configurações, enquanto ~/.hermes/.env contém os segredos. auth.json, SOUL.md, MEMORY.md e skills/ são gerenciados diretamente pelo Hermes — você pode editar SOUL.md manualmente, mas o restante é modificado pelo próprio agente.4
  • O Hermes é o sucessor do OpenClaw. Se você estiver migrando, hermes claw migrate importará automaticamente mais de 30 categorias de estado.5
  • A qualidade do serviço depende do seu modelo auxiliar. Visão, resumo de conteúdo da web, compressão e gravação da memória usam um LLM auxiliar separado. Por padrão, ele é o Gemini Flash, selecionado por detecção automática (OpenRouter → Nous → Codex) — se nenhum deles estiver configurado, esses recursos perderão qualidade silenciosamente até que você direcione os slots auxiliares ao seu provedor principal.4

O que muda na v0.14

A v0.14.0 não se concentra tanto em um único recurso de destaque, mas em reduzir o atrito da configuração e ampliar os ambientes em que o Hermes pode ser executado.19 As principais mudanças operacionais:

  • A instalação e a inicialização estão mais leves. pip install hermes-agent funciona pelo PyPI, adaptadores pesados são instalados sob demanda no primeiro uso e o fluxo de inicialização adia trabalho suficiente para reduzir a inicialização a frio em cerca de 19 segundos. (Desde então, a v0.19.0 descontinuou instalações via pip — consulte Instalação.)
  • Assinaturas podem se tornar endpoints locais de API. hermes proxy transforma provedores baseados em OAuth, como Claude Pro, ChatGPT Pro e SuperGrok, em um endpoint local compatível com OpenAI para ferramentas como Codex, Aider, Cline e Continue.
  • O alcance do gateway foi ampliado. LINE e SimpleX Chat elevam para 22 o número de plataformas, Microsoft Teams está integrado de ponta a ponta, o preenchimento retroativo do histórico do Discord vem ativado por padrão e os prompts clarify do Telegram/Discord agora usam botões nativos.
  • A verificação durante a gravação foi aprimorada. Após as edições, o Hermes pode apresentar, a cada turno, resumos das alterações em arquivos e diagnósticos semânticos do servidor de linguagem antes do turno seguinte, aproximando-o de um trabalho de agente orientado por evidências.
  • As ferramentas para desktop e mídia estão mais abrangentes. computer_use funciona por meio do cua-driver para provedores que não sejam Anthropic, video_generate está unificado por trás de backends intercambiáveis e vision_analyze envia pixels brutos a modelos que realmente conseguem enxergar.

Todas as seções abaixo se baseiam na documentação oficial em hermes-agent.nousresearch.com/docs e na árvore de código-fonte em github.com/NousResearch/hermes-agent. Cada afirmação factual inclui uma nota de rodapé que aponta para a página oficial específica da qual foi extraída.

Como o Hermes funciona: o modelo mental

O Hermes é estruturado em torno de um único loop de conversa que pode ser invocado por qualquer ponto de entrada. Os pontos de entrada são a CLI (cli.py), o gateway de mensagens (gateway/run.py), o adaptador ACP para integração com editores, o executor em lote e um servidor API.3 No fim, todos eles chamam AIAgent.run_conversation() em run_agent.py, que:

  1. Monta o prompt do sistema usando SOUL.md, MEMORY.md, USER.md, skills, arquivos de contexto e orientações sobre ferramentas por meio de prompt_builder.py3
  2. Resolve o provedor em tempo de execução por meio de runtime_provider.py — é nessa etapa que o método de autenticação, a URL base e o modo API são escolhidos3
  3. Chama o provedor usando um dos três modos API: chat_completions, codex_responses ou anthropic_messages3
  4. Encaminha todas as chamadas de ferramentas retornadas por meio de model_tools.py e do registro central de ferramentas (tools/registry.py)3
  5. Repete o processo até que o modelo produza uma resposta final e, em seguida, salva a sessão no SQLite com FTS53

Entender esse loop é importante porque todos os recursos — personalidades, memória, skills, compressão e fallback — se conectam a uma dessas etapas. Quando você encontra uma chave de configuração e se pergunta para que ela serve, a resposta geralmente é: “ela ajusta a etapa 1, 2, 3 ou 4 do loop acima”.

Núcleo independente de plataforma. Uma única classe AIAgent atende à CLI, ao gateway, ao ACP, ao processamento em lote e ao servidor API. As diferenças entre plataformas ficam no ponto de entrada, não no agente em si.3 É por isso que os mesmos comandos slash funcionam no terminal e no Telegram — eles são encaminhados por um COMMAND_REGISTRY compartilhado em hermes_cli/commands.py.6

A estrutura de diretórios é o sistema. O Hermes armazena tudo em ~/.hermes/ (ou em $HERMES_HOME para profiles que não sejam o padrão):4

~/.hermes/
├── config.yaml        # Settings (model, terminal, TTS, compression, etc.)
├── .env               # API keys and secrets
├── auth.json          # OAuth provider credentials (Nous Portal, Codex, Anthropic)
├── SOUL.md            # Primary agent identity (slot #1 in system prompt)
├── memories/          # Persistent memory (MEMORY.md, USER.md)
├── skills/            # Bundled + agent-created + hub-installed skills
├── cron/              # Scheduled jobs
├── sessions/          # Gateway session state
└── logs/              # agent.log, gateway.log, errors.log (secrets auto-redacted)

Cada arquivo acima tem uma função específica; nenhuma delas se sobrepõe. Se você quiser saber “onde o Hermes armazena X”, a resposta estará entre esses arquivos.

Novidades da v0.19.0 (versão Quicksilver)

O Hermes Agent v0.19.0 (tag v2026.7.20, 20 de julho de 2026) recebeu esse nome em referência à velocidade do próprio deus mensageiro: a essência da versão é a agilidade pura, com uma redução de cerca de 80% no tempo até o primeiro token da primeira interação em todas as plataformas. Em torno desse eixo estão o gerenciamento de cobranças pelo terminal, fontes de segredos provenientes de gerenciadores de senhas, aprovações inteligentes por padrão, subagentes observáveis e entrega de respostas resistente a falhas. O período desde a v0.18.0 é o maior da história do projeto: cerca de 2.245 commits, aproximadamente 1.065 PRs mesclados, por volta de 3.300 issues encerradas e mais de 450 colaboradores da comunidade.23

  • Cerca de 80% mais rápido até o primeiro token, em todos os lugares. O intervalo entre o envio a frio e o encaminhamento caiu de aproximadamente 4,3 s para 0,9 s tanto na CLI quanto no gateway, na TUI, no desktop e no cron — a detecção de recursos do Discord foi retirada do caminho crítico, a sondagem do Ollama é ignorada para provedores conhecidos que não usam Ollama e tarefas bloqueantes foram removidas da inicialização do agente. A latência percebida também recebeu atenção especial: agora, os modelos de raciocínio transmitem seus pensamentos ao vivo por padrão (display.show_reasoning fica ATIVADO), e a caixa de resposta é atualizada a cada token, não a cada linha.23
  • Uma onda de melhorias na renderização do desktop e da TUI. O aplicativo para desktop passou por uma reformulação de desempenho com cerca de 20 PRs: consumo de CPU 14 vezes menor no separador de Markdown transmitido, graças à análise léxica incremental de blocos; diffs virtualizados no painel de revisão; troca ágil entre sessões com transcrições grandes; e o fim das novas renderizações da barra lateral e das linhas de ferramentas a cada token. Agora, a TUI renderiza o Markdown transmitido de forma incremental, bloco a bloco.23
  • As instalações por pip e Homebrew estão obsoletas. Agora, os dois métodos são classificados como instalações “legadas e sem suporte” — todas as interfaces exibem avisos, mas sem bloquear o uso, e a publicação no PyPI/Homebrew será descontinuada. O instalador de uma linha é o método compatível; se você instalou pelo pip ou brew, planeje a migração agora.23
  • Os segredos podem vir do seu gerenciador de senhas. Uma nova interface conectável SecretSource busca segredos do Bitwarden e do 1Password (referências op://) durante o carregamento, permitindo o uso simultâneo de vários cofres, com precedência determinística, avisos de conflito e rastreamento da origem de cada variável — as chaves API não precisam mais ficar em um arquivo .env de texto simples. Outros provedores de cofres poderão ser adicionados futuramente como plugins.23
  • As aprovações inteligentes agora são o padrão. Quando o Hermes quer executar um comando sinalizado, um revisor LLM independente o avalia, em vez de solicitar sua confirmação para cada comando — e cada veredito vale somente para aquele comando exato. Regras de bloqueio definidas pelo usuário impedem comandos correspondentes até mesmo no modo YOLO, /deny <reason> comunica o motivo da sua recusa para que o agente corrija o rumo, e a ação de aprovação pre_tool_call do plugin (restaurada com chaves de regras) encaminha uma chamada de ferramenta para aprovação humana.23
  • Cobranças pelo terminal: /subscription e /topup. Gerencie seu plano do Nous Portal sem sair do terminal — consulte o plano e o saldo restante, veja exatamente quanto custará um upgrade ou quando um downgrade entrará em vigor e aplique a alteração com a opção de desfazê-la. O aplicativo para desktop recebe uma aba correspondente de configurações de cobrança.23
  • Acompanhe o trabalho dos subagentes; nunca perca uma resposta concluída. Os envios de delegate_task retornam arquivos de transcrição ao vivo que você pode acompanhar com tail -f assim que os subagentes são iniciados — cada chamada de ferramenta, resultado e resposta transmitida fica em um log legível por pessoas para cada agente filho. As conclusões de delegações em segundo plano persistem após reinicializações, e as respostas finais do gateway são registradas em um livro-razão de obrigações de entrega no state.db e reenviadas na próxima inicialização caso o gateway falhe durante o envio. A opção de configuração max_async_children está obsoleta e foi substituída por limites unificados de concorrência para delegações.23
  • Um gateway, vários profiles. Um único gateway multiplexado que compartilha o mesmo token de bot pode encaminhar guildas, canais ou threads específicos para profiles diferentes — cada um com configurações, skills, memória e segredos totalmente isolados — com uma substituição GATEWAY_MULTIPLEX_PROFILES. O índice de roteamento foi transferido para state.db; agora, sessions.json é apenas um espelho legado opcional.23
  • Uma onda de novidades em provedores e modelos. O Fireworks AI recebe integração nativa (estimativa de custos e segunda posição no seletor de provedores), acompanhado pelo DeepInfra e pelo Upstage Solar. Os catálogos passam a incluir GPT-5.6 (Sol/Terra/Luna + Pro, com integração completa), grok-4.5 (GA), kimi-k3 (com o kimi-k2.x descontinuado) e Claude Sonnet 5 com integração completa. Uma opção enabled: false por provedor e a configuração excluded_providers removem provedores não utilizados dos seletores de /model e da resolução.23
  • O esforço de raciocínio passa a ser ajustável. Os novos níveis de esforço max e ultra chegam a todas as interfaces, com substituições por modelo na configuração, esforço por slot nas predefinições de MoA (os consultores raciocinam intensamente, enquanto o sintetizador permanece rápido), esforço por tarefa para modelos auxiliares e um /reasoning limitado à sessão na CLI.23
  • Interfaces CLI e MCP. hermes sessions export gera formatos Markdown, Quarto, HTML, somente prompt e traces do Hugging Face, com uma limpeza opcional por meio de --redact; /model --once permite substituir o modelo por uma única interação; invocações de slash-skills podem ser combinadas (/skill-a /skill-b do XYZ); --safe-mode ajuda na solução de problemas; hermes config get/unset completam o gerenciamento de configurações; hermes serve se torna um verdadeiro backend headless; e as ferramentas MCP adotam a convenção de nomenclatura mcp__server__tool.23

Se você estiver atualizando a partir da v0.18.x, duas mudanças merecem atenção antes de qualquer outra: instalações por pip ou Homebrew agora são sinalizadas como legadas e sem suporte (migre para o instalador de uma linha), e max_async_children está obsoleto e foi substituído pelos limites unificados de concorrência para delegações. Todo o restante é adicional — os principais motivos para atualizar são a redução de cerca de 80% na latência da primeira interação, as aprovações inteligentes e o livro-razão de entregas, que impede que respostas concluídas sejam perdidas em caso de falha.

Novidades da v0.18.0 (The Judgment Release)

O Hermes Agent v0.18.0 (tag v2026.7.1, 1º de julho de 2026) recebeu esse nome em referência ao julgamento: o agente verifica o próprio trabalho em vez de apenas afirmar que teve sucesso, com um raciocínio em conjunto que você realmente pode inspecionar. A versão também resolve todo o backlog P0/P1 — cerca de 692 itens de prioridade máxima solucionados em 12 dias.22

  • Mixture-of-Agents como modelo de primeira classe. Agora, o MoA pode ser selecionado como qualquer outro modelo em todas as interfaces, e o raciocínio em conjunto fica visível: a saída completa de cada modelo de referência é exibida em um bloco próprio e identificado, com streaming da resposta em tempo real — você pode acompanhar o conjunto raciocinando em vez de receber uma resposta mesclada e opaca.22
  • Contratos de conclusão para /goal. Antes de informar que um objetivo foi concluído, o agente verifica o próprio trabalho executando as verificações do projeto, em vez de simplesmente afirmar que teve sucesso — aplicando o julgamento a si mesmo.22
  • /learn — transforme a descrição de qualquer coisa em uma skill. Transforme um fluxo de trabalho em uma skill reutilizável descrevendo-o; as skills geradas seguem automaticamente as convenções do CONTRIBUTING.md do repositório.22
  • Linha do tempo de /journey. Um histórico visual da memória e das skills ao longo do tempo, com edição, além de um grafo de memória no desktop.22
  • Distribuição de subagentes em segundo plano. Delegue várias tarefas executadas simultaneamente sem bloquear a conversa — o único subagente em segundo plano da v0.17.0 se transforma em uma frota.22
  • Projects no desktop. Projects de programação de primeira classe, com um modelo de organização por projeto/repositório/lane.22
  • Gateway com redução a zero. Gateways podem ficar inativos quando ociosos e coordenar o esvaziamento para permitir implantações sem interrupções — algo relevante para quem executa o Hermes como um serviço sempre ativo.22
  • Compatibilidade com Google Vertex AI. Acesso ao Gemini por meio de contas de serviço do GCP, com renovação automática de token OAuth2, passando a integrar o catálogo de provedores.22
  • Comando de editor /prompt. Abre o $EDITOR para escrever prompts com várias linhas em vez de obrigar você a lidar com a linha de entrada.22

Se você estiver atualizando da v0.17.x, nada aqui quebra a CLI. Os principais motivos para atualizar são os contratos de conclusão (objetivos que verificam a si mesmos), o MoA de primeira classe com conjuntos inspecionáveis e o /learn para registrar skills.

Novidades da v0.17.0 (The Reach Release)

O Hermes Agent v0.17.0 (tag v2026.6.19, 19 de junho de 2026) recebeu esse nome em referência ao alcance que o agente passou a ter — novos canais de mensagens, novos provedores de modelos e controles mais avançados no desktop e no dashboard. Ela acrescenta recursos à v0.16.x; a interface da CLI permanece inalterada.21

  • Novos canais de mensagens. Agora, o iMessage funciona sem um Mac intermediário por meio do Photon Spectrum (OAuth com código do dispositivo, hermes photon login); a API oficial do WhatsApp Business Cloud é um adaptador da Meta que elimina a necessidade de um processo de bridge; o SimpleX passa a oferecer grupos, anexos nativos, agrupamento de texto e aceitação automática; e o Raft chega como um plugin de plataforma incluído, com um design de canal de ativação que garante privacidade por contrato.21
  • Novos modelos e provedores. O catálogo passa a incluir z-ai/glm-5.2 (contexto de 1M), anthropic/claude-fable-5, laguna-m.1, nemotron-3-ultra e grok-composer-2.5-fast (o modelo do Cursor por meio da OAuth da xAI, com contexto de 200k). O padrão da xAI mudou para grok-build-0.1, e os modelos adaptativos da Anthropic agora seguem o contrato moderno de raciocínio (eles nunca enviam um campo reasoning).21
  • Desktop e dashboard. O desktop passa a oferecer subagentes em segundo plano, com streaming ao vivo da atividade delegada em “janelas de acompanhamento” (delegate_task(background=true)), seletor de modelo no Composer, atalhos de teclado remapeáveis, notificações nativas do sistema operacional, rascunhos do Composer por thread, temas do VS Code Marketplace e interface em japonês e chinês tradicional. O dashboard ganha um construtor completo de profiles (modelo/skills/MCPs sem editar o config.yaml), um seletor global de profile, um Skills Hub reformulado com verificação de segurança, Automation Blueprints (modelos parametrizados disponíveis em formulário, comando de barra, conversa e documentação) e um login seguro que retorna 401 atrás da camada de OAuth.21
  • Skills e ferramentas. Agora, image_generate pode editar e transformar uma imagem de origem, além de criar uma do zero, em todos os provedores de imagem compatíveis; a ferramenta memory ganhou um array operations para adicionar, substituir e remover itens atomicamente em lote com uma única chamada; uma nova skill simplify-code executa uma análise e limpeza paralela por 3 agentes, condicionada a uma classificação de risco baseada na Cerca de Chesterton; e o booleano write_approval substitui o write_mode de 3 estados.21
  • Arquitetura. Subagentes em segundo plano retornam um identificador imediatamente e reinserem o resultado como um novo turno; um manipulador de elicitação de MCP permite confirmar durante a chamada de uma ferramenta, e ferramentas de MCP que se conectam posteriormente ficam disponíveis entre os turnos (sem comprometer o cache); o cron se torna um CronScheduler conectável, com o Chronos como provedor de cron gerenciado; e um novo escopo Managed (/etc/hermes) permite que um administrador fixe configurações que o usuário não pode alterar, além de um relay Gateway-Gateway para topologias com vários gateways.21
  • Novos comandos. /version, /billing (faturamento interativo no terminal), hermes photon login (autenticação do iMessage) e hermes curator run --consolidate — agora, a consolidação é opcional, portanto a curadoria rotineira em segundo plano não consome tokens.21
  • Segurança. Instalação

O instalador de uma linha é o método de instalação compatível. Ele cuida de Python, uv, Node.js, ripgrep, ffmpeg, da clonagem do repositório, do ambiente virtual e do comando global hermes.7

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

As instalações via pip e Homebrew estão obsoletas desde a v0.19.0. O pacote PyPI introduzido na v0.14.0 (pip install hermes-agent) e a fórmula do Homebrew agora são classificados como instalações “legadas sem suporte” — todas as interfaces exibem um aviso (sem bloquear) quando o Hermes detecta uma delas, e está previsto o encerramento da publicação no PyPI e no Homebrew. Se você instalou via pip ou brew, migre para o instalador acima.23

Funciona no Linux, macOS, WSL2 e Android/Termux (o instalador detecta o Termux automaticamente e muda para um pacote Android testado).7 A v0.14.0 adiciona suporte nativo ao Windows em beta inicial por meio de um instalador do PowerShell, mas o WSL2 continua sendo a recomendação mais segura para uso em produção até que a opção para Windows amadureça.19

Quando a instalação terminar:

source ~/.bashrc    # or ~/.zshrc
hermes              # Start chatting

O único pré-requisito é o git. O instalador provisiona automaticamente o Python 3.11 via uv (sem exigir sudo), o Node.js v22 (para automação do navegador e a ponte do WhatsApp), o ripgrep e o ffmpeg.7

Verifique a instalação

hermes version      # Check version
hermes doctor       # Diagnose config/dependency issues
hermes status       # Show current configuration + auth state
hermes dump         # Copy-pasteable setup summary for debugging

hermes doctor informa exatamente o que está faltando e como corrigir.7 hermes dump é o comando de diagnóstico que você deve colar em uma issue do GitHub ou em uma conversa no Discord ao pedir ajuda — ele gera um resumo em texto simples de toda a sua configuração, com os dados secretos ocultados.8

Autenticação e provedores

Hermes oferece suporte nativo a cerca de 22 provedores, além de endpoints personalizados (a v0.19.0 adiciona Fireworks AI, DeepInfra e Upstage Solar), e três caminhos distintos de autenticação. Veja toda a superfície de autenticação, organizada por caminho para que você encontre aquele que corresponde ao que tem disponível.

Os três caminhos de autenticação

Todos os provedores do Hermes seguem um destes três padrões de autenticação:

Caminho 1 — chave de API no .env. Coloque sua chave em ~/.hermes/.env, e o Hermes a lerá na inicialização. Usado por OpenRouter, AI Gateway, z.ai/GLM, Kimi/Moonshot, MiniMax (incluindo MiniMax China), Alibaba Cloud/DashScope, Kilo Code, OpenCode Zen, OpenCode Go, DeepSeek, Hugging Face, Google/Gemini e pela maioria dos provedores externos.2 Desde a v0.19.0, a chave não precisa mais ficar em um arquivo de texto simples: uma interface conectável SecretSource pode buscar segredos no Bitwarden ou no 1Password (referências op://) durante o carregamento, com vários cofres habilitados simultaneamente, precedência determinística, avisos de conflito e procedência por variável — o .env continua sendo a opção de fallback. (Isso é diferente do token de inicialização do Bitwarden Secrets Manager introduzido na v0.15.0, que consolidava as chaves dos provedores por trás de um único token; SecretSource substitui o próprio arquivo de texto simples, e futuros provedores de cofres podem ser adicionados como plugins.)23

Caminho 2 — OAuth por meio de hermes model ou hermes auth. Inicia um fluxo de código de dispositivo, abre um navegador, armazena as credenciais em ~/.hermes/auth.json (e pode importar credenciais existentes de ferramentas como Claude Code ou Codex CLI). Usado por Nous Portal, OpenAI Codex (conta do ChatGPT), GitHub Copilot e Anthropic (Claude Pro/Max).2

Caminho 3 — endpoint personalizado no config.yaml. Para qualquer API compatível com OpenAI — Ollama, vLLM, SGLang, llama.cpp, LM Studio, proxy LiteLLM, Together AI, Groq, Azure OpenAI ou seu próprio servidor auto-hospedado. Configure uma vez em hermes model → Custom endpoint; depois, a configuração será persistida no config.yaml.2

Anthropic: três métodos de autenticação

Anthropic tem sua própria seção porque o Hermes oferece três caminhos distintos para acessar o Claude, e escolher o caminho certo faz diferença. Segundo a documentação upstream:2

# Method 1: API key (pay-per-token)
export ANTHROPIC_API_KEY=***
hermes chat --provider anthropic --model claude-sonnet-4-6

# Method 2: OAuth through hermes model (preferred)
# Uses Claude Code's credential store when available
hermes model

# Method 3: Manual setup-token (fallback/legacy)
export ANTHROPIC_TOKEN=***
hermes chat --provider anthropic

# Auto-detect Claude Code credentials
hermes chat --provider anthropic   # reads Claude Code files automatically

Quando você escolhe OAuth do Anthropic por meio de hermes model, o Hermes prioriza o armazenamento de credenciais do próprio Claude Code em vez de copiar o token para ~/.hermes/.env. Assim, as credenciais renováveis do Claude continuam podendo ser renovadas.2 Se você já usa o Claude Code na mesma máquina, este é o caminho mais simples.

Para fixar permanentemente o Anthropic no config.yaml:

model:
  provider: "anthropic"
  default: "claude-sonnet-4-6"

--provider claude e --provider claude-code também funcionam como formas abreviadas de --provider anthropic.2

GitHub Copilot: dois modos

O Copilot é compatível com dois modos: API direta do Copilot (recomendado) e Copilot ACP (que inicia o CLI local do Copilot como subprocesso).2

# Direct Copilot API
hermes chat --provider copilot --model gpt-5.4

# Copilot ACP (requires the Copilot CLI in PATH + an existing copilot login)
hermes chat --provider copilot-acp --model copilot-acp

A autenticação é verificada nesta ordem, conforme a documentação upstream:2 1. Variável de ambiente COPILOT_GITHUB_TOKEN 2. Variável de ambiente GH_TOKEN 3. Variável de ambiente GITHUB_TOKEN 4. Fallback para o CLI gh auth token 5. Login por código de dispositivo OAuth via hermes model

O tipo de token faz diferença. A API do Copilot não oferece suporte a Personal Access Tokens clássicos (ghp_*). Os tipos compatíveis são tokens OAuth (gho_*), PATs de escopo refinado (github_pat_* com a permissão Copilot Requests) e tokens do GitHub App (ghu_*). Se gh auth token retornar um token ghp_*, use hermes model para fazer a autenticação por OAuth.2

Provedores chineses de IA (suporte nativo)

O Hermes oferece suporte integrado a z.ai/GLM, Kimi/Moonshot, MiniMax (endpoints globais e da China) e Alibaba Cloud, com IDs de provedor dedicados.2

# z.ai / ZhipuAI GLM
hermes chat --provider zai --model glm-5                 # Requires: GLM_API_KEY

# Kimi / Moonshot AI
hermes chat --provider kimi-coding --model kimi-for-coding   # Requires: KIMI_API_KEY

# MiniMax (global)
hermes chat --provider minimax --model MiniMax-M2.7          # Requires: MINIMAX_API_KEY

# MiniMax (China)
hermes chat --provider minimax-cn --model MiniMax-M2.7       # Requires: MINIMAX_CN_API_KEY

# Alibaba Cloud / DashScope (Qwen)
hermes chat --provider alibaba --model qwen3.5-plus          # Requires: DASHSCOPE_API_KEY

As URLs base podem ser substituídas pelas variáveis de ambiente GLM_BASE_URL, KIMI_BASE_URL, MINIMAX_BASE_URL, MINIMAX_CN_BASE_URL ou DASHSCOPE_BASE_URL.2

Z.AI detecta o endpoint automaticamente. Ao usar o provedor z.ai/GLM, o Hermes testa vários endpoints (globais, da China e variantes para programação) para encontrar um que aceite sua chave de API. O endpoint funcional é armazenado automaticamente em cache — a maioria dos usuários não precisa definir GLM_BASE_URL.2

xAI (Grok) habilita automaticamente o cache de prompts. Quando a URL base contém x.ai, o Hermes envia o cabeçalho x-grok-conv-id em todas as solicitações para encaminhá-las ao mesmo servidor durante uma sessão de conversa, reutilizando os prompts de sistema e o histórico armazenados em cache.2 É automático; nenhuma configuração é necessária.

O comando hermes auth

hermes auth é o comando de gerenciamento de credenciais para pools e credenciais OAuth.6

hermes auth                              # Interactive wizard
hermes auth list                         # Show all credential pools
hermes auth list openrouter              # Show one provider's pool
hermes auth add openrouter --api-key sk-or-v1-xxx
hermes auth add anthropic --type oauth
hermes auth remove openrouter 2          # Remove by index
hermes auth reset openrouter             # Clear cooldowns

Os pools de credenciais permitem alternar entre várias chaves de API ou tokens OAuth do mesmo provedor — algo útil para distribuir limites de requisições entre várias chaves sem alterar o código.6 Os comandos legados hermes login / hermes logout foram removidos; use hermes auth.6

Endpoints personalizados e auto-hospedados

O Hermes funciona com qualquer endpoint de API compatível com OpenAI. Se um servidor implementar /v1/chat/completions, você poderá direcionar o Hermes para ele.2

Configuração interativa (recomendada):

hermes model
# Select "Custom endpoint (self-hosted / VLLM / etc.)"
# Enter: API base URL, API key, Model name

config.yaml manual:

model:
  default: your-model-name
  provider: custom
  base_url: http://localhost:8000/v1
  api_key: your-key-or-leave-empty-for-local

As duas abordagens persistem as configurações no config.yaml, que é a fonte única da verdade para o modelo principal, o provedor e a URL base.2 As variáveis de ambiente legadas OPENAI_BASE_URL e LLM_MODEL não são mais lidas na configuração do modelo principal — use hermes model ou edite o config.yaml diretamente.2 (OPENAI_BASE_URL + OPENAI_API_KEY ainda são respeitadas como fallback no caminho auxiliar de roteamento provider: "main", portanto, não as exclua sem verificar caso você as use nesse contexto.)4

Como trocar endpoints personalizados durante uma sessão:

/model custom:qwen-2.5             # Custom endpoint with explicit model
/model custom                      # Auto-detect the model from the endpoint
/model custom:local:qwen-2.5       # Named custom provider "local"
/model custom:work:llama3          # Named custom provider "work"
/model openrouter:claude-sonnet-4  # Back to a cloud provider

/model custom (sozinho, sem o nome de um modelo) consulta a API /v1/models do seu endpoint e seleciona o modelo automaticamente caso haja exatamente um carregado — útil para servidores locais que executam um único modelo.2

Servidores LLM locais (modelos de configuração)

A documentação upstream traz guias completos de configuração para Ollama, vLLM, SGLang, llama.cpp e LM Studio. Estes são os principais comandos que você realmente executará. Cada um foi desenvolvido para produzir um endpoint funcional para o qual o Hermes possa ser direcionado.2

Ollama — o caminho local mais simples, sem configuração:

ollama pull qwen2.5-coder:32b
OLLAMA_CONTEXT_LENGTH=32768 ollama serve   # Raise from 4k default
hermes model   # Custom endpoint → http://localhost:11434/v1 → qwen2.5-coder:32b

Armadilha crítica do Ollama: por padrão, o Ollama usa comprimentos de contexto muito baixos (4.096 tokens com menos de 24 GB de VRAM). Você precisa aumentá-los por meio de OLLAMA_CONTEXT_LENGTH ou de um Modelfile — a API compatível com OpenAI não aceita o comprimento de contexto do cliente, portanto, o Hermes não pode configurá-lo para você.2 Para uso com agentes, defina pelo menos 16k–32k.

vLLM — servidor de GPU de alto desempenho:

pip install vllm
vllm serve meta-llama/Llama-3.1-70B-Instruct \
  --port 8000 \
  --max-model-len 65536 \
  --tensor-parallel-size 2 \
  --enable-auto-tool-choice \
  --tool-call-parser hermes

As chamadas de ferramentas exigem --enable-auto-tool-choice e --tool-call-parser <name>. Parsers compatíveis: hermes (Qwen 2.5, Hermes 2/3), llama3_json, mistral, deepseek_v3, deepseek_v31, xlam, pythonic. Sem essas flags, as chamadas de ferramentas serão retornadas como texto simples.2

SGLang — servidor rápido com RadixAttention para reutilização do cache KV:

pip install "sglang[all]"
python -m sglang.launch_server \
  --model meta-llama/Llama-3.1-70B-Instruct \
  --port 30000 \
  --context-length 65536 \
  --tp 2 \
  --tool-call-parser qwen

Armadilha do SGLang: o valor padrão de max_tokens é 128. Defina --default-max-tokens no servidor ou configure model.max_tokens no config.yaml caso as respostas sejam cortadas.2

llama.cpp / llama-server — CPU e Metal no Apple Silicon:

./build/bin/llama-server \
  --jinja -fa \
  -c 32768 \
  -ngl 99 \
  -m models/qwen2.5-coder-32b-instruct-Q4_K_M.gguf \
  --port 8080 --host 0.0.0.0

--jinja é obrigatório para chamadas de ferramentas. Sem essa opção, o llama-server ignora completamente o parâmetro tools, e o modelo tenta chamar ferramentas escrevendo JSON no texto da resposta — algo que o Hermes não consegue interpretar como chamadas reais de ferramentas.2

LM Studio — aplicativo desktop com interface gráfica:

Inicie o servidor pelo aplicativo LM Studio (aba Developer → Start Server) ou pelo CLI: lms server start (inicia na porta 1234) e lms load qwen2.5-coder --context-length 32768.2 Depois, direcione hermes model para http://localhost:1234/v1.

Armadilha crítica do LM Studio: o LM Studio lê o comprimento do contexto nos metadados do modelo, mas muitos modelos GGUF informam valores padrão de 2048 ou 4096. Sempre defina explicitamente o comprimento do contexto nas configurações de modelo do LM Studio — clique no ícone de engrenagem ao lado do seletor de modelos, defina “Context Length” como pelo menos 16384 (de preferência, 32768) e recarregue o modelo.2

Provedores personalizados nomeados

Se você trabalha com vários endpoints personalizados (um servidor de desenvolvimento local e um servidor GPU remoto, por exemplo), defina-os como provedores personalizados nomeados no config.yaml:2

custom_providers:
  - name: local
    base_url: http://localhost:8080/v1
    # api_key omitted — Hermes uses "no-key-required" for keyless local servers
  - name: work
    base_url: https://gpu-server.internal.corp/v1
    api_key: corp-api-key
    api_mode: chat_completions      # optional, auto-detected from URL
  - name: anthropic-proxy
    base_url: https://proxy.example.com/anthropic
    api_key: proxy-key
    api_mode: anthropic_messages    # for Anthropic-compatible proxies

Depois, alterne entre eles durante a sessão usando a sintaxe tripla:

/model custom:local:qwen-2.5
/model custom:work:llama3-70b
/model custom:anthropic-proxy:claude-sonnet-4

Você também pode selecionar provedores personalizados nomeados no menu interativo de hermes model.2

Arquitetura conectável de provedores (v0.13.0+)

A v0.13.0 inclui uma ABC ProviderProfile, além de uma pasta plugins/model-providers/, para que provedores externos de inferência possam ser adicionados sem modificações no núcleo.18 Se um provedor oferecer um modo de API compatível com OpenAI, Anthropic ou Codex, você poderá implementar uma subclasse de ProviderProfile que declare o caminho de autenticação, a URL base, o catálogo de modelos e os cabeçalhos de cache; o Hermes fará a resolução pelo mesmo caminho runtime_provider.py usado pelos provedores integrados. Esta é a mudança arquitetural por trás da expansão de provedores da v0.13.0: em vez de editar o código principal para adicionar um provedor, você distribui um plugin.

Proxy local compatível com OpenAI (v0.14.0+)

hermes proxy expõe um endpoint local compatível com OpenAI, executado pelo provedor OAuth no qual o Hermes já está conectado — Claude Pro, ChatGPT Pro, SuperGrok ou outro provedor compatível configurado.19 Isso significa que ferramentas que esperam uma API no estilo da OpenAI, incluindo Codex CLI, Aider, Cline, Continue ou scripts personalizados, podem reutilizar a autenticação do Hermes vinculada à sua assinatura sem uma chave de API separada. Trate o proxy como infraestrutura local de desenvolvimento: defina o vínculo de rede de forma intencional, não o exponha amplamente e considere os termos específicos do provedor.

Detecção do comprimento de contexto

Segundo a documentação upstream, duas configurações são confundidas com frequência:2

  • context_length — a janela total de contexto (orçamento combinado de tokens de entrada e saída, por exemplo, 1.000.000 para Claude Opus 4.7 ou 200.000 para Sonnet 4.6). O Hermes usa esse valor para decidir quando comprimir o histórico.
  • model.max_tokens — o limite de saída (quantidade máxima de tokens que o modelo pode gerar em uma única resposta). Não tem relação com o tamanho do histórico.

Defina context_length quando a detecção automática identificar incorretamente o tamanho da janela:

model:
  default: "qwen3.5:9b"
  base_url: "http://localhost:8080/v1"
  context_length: 131072      # tokens

O Hermes usa uma cadeia de resolução com várias fontes para detectar janelas de contexto: substituição na configuração → configuração por modelo do provedor personalizado → cache persistente → /models do endpoint → /v1/models do Anthropic → API do OpenRouter → Nous Portal → models.dev (registro mantido pela comunidade com mais de 3.800 modelos) → valores padrão de fallback (128K).2 O sistema considera o provedor, portanto, o mesmo modelo pode ter limites de contexto diferentes dependendo de quem o disponibiliza (por exemplo, claude-opus-4.6 tem 1M diretamente no Anthropic, mas 128K no GitHub Copilot).2

Rotação e fallback de provedores

Pools de credenciais. Quando você tem várias chaves de API para o mesmo provedor, configure uma estratégia de rotação por meio de hermes auth. É assim que você distribui limites de requisições entre várias chaves.6

Modelo de fallback. Configure um provider:model de backup para o qual o Hermes alternará automaticamente quando o modelo principal falhar (limites de requisições, erros do servidor ou falhas de autenticação):2

fallback_model:
  provider: openrouter            # required
  model: anthropic/claude-sonnet-4  # required
  # base_url: http://localhost:8000/v1    # optional, for custom endpoints
  # api_key_env: MY_CUSTOM_KEY           # optional, env var name

O fallback troca o modelo e o provedor durante a sessão sem perder sua conversa. Ele é acionado no máximo uma vez por sessão.2 Provedores compatíveis com fallback: openrouter, nous, openai-codex, copilot, copilot-acp, anthropic, huggingface, zai, kimi-coding, minimax, minimax-cn, deepseek, ai-gateway, opencode-zen, opencode-go, kilocode, alibaba, custom.2

Modelos auxiliares

O Hermes usa modelos “auxiliares” leves para tarefas secundárias: análise de imagens, resumo de páginas da web, análise de capturas de tela do navegador, classificação para aprovação de comandos perigosos, compressão de contexto, resumo de buscas em sessões, correspondência de skills, despacho de ferramentas MCP e gravação da memória.4 Por padrão, essas tarefas usam Gemini Flash por meio de detecção automática (OpenRouter → Nous → Codex).

Você pode configurar o modelo e o provedor usados em cada tarefa auxiliar. Cada slot auxiliar usa os mesmos três controles: provider, model, base_url.4

auxiliary:
  vision:
    provider: "auto"                # "auto", "openrouter", "nous", "codex", "main", etc.
    model: ""                       # e.g. "openai/gpt-4o", "google/gemini-2.5-flash"
    base_url: ""                    # Custom OpenAI-compatible endpoint
    api_key: ""                     # Falls back to OPENAI_API_KEY
    timeout: 30
    download_timeout: 30
  web_extract:
    provider: "auto"
    model: ""
    timeout: 360
  approval:
    provider: "auto"
    model: ""
    timeout: 30
  compression:
    timeout: 120
  session_search: { provider: "auto", model: "", timeout: 30 }
  skills_hub:    { provider: "auto", model: "", timeout: 30 }
  mcp:           { provider: "auto", model: "", timeout: 30 }
  flush_memories:{ provider: "auto", model: "", timeout: 30 }

A opção de provedor "main" significa “usar o mesmo provedor do meu agente principal” — válida somente nas configurações auxiliary:, compression: e fallback_model:. Ela não é válida na configuração de nível superior model.provider. Se você usar um endpoint personalizado compatível com OpenAI como modelo principal, defina provider: custom na seção model:.4

Por que isso é importante: se você configurou apenas OAuth do Anthropic (sem uma chave do OpenRouter), os recursos de visão, resumo da web e compressão terão desempenho reduzido ou falharão, pois a cadeia padrão de fallback auxiliar tenta primeiro o OpenRouter. Adicione uma OPENROUTER_API_KEY para tarefas auxiliares ou reconfigure cada slot auxiliar para usar seu provedor principal:

auxiliary:
  vision:
    provider: "main"
  web_extract:
    provider: "main"

Esta é, de longe, a armadilha mais comum por trás de “meus recursos não funcionam e não mostram nenhum erro” para novos usuários do Hermes.

Sistema de configuração

O Hermes tem um sistema de configuração em camadas. Entender a ordem de precedência é essencial, porque as camadas superiores substituem as inferiores, e uma dessas camadas é um registro global de provedores que você não consegue ver no config.yaml.

Estrutura dos arquivos de configuração

Segundo a documentação oficial, estes são os arquivos que compõem uma configuração do Hermes:4

~/.hermes/
├── config.yaml       # All settings (model, terminal, TTS, compression, memory, toolsets, ...)
├── .env              # Secrets (API keys, bot tokens, passwords)
├── auth.json         # OAuth provider credentials (Nous Portal, Codex, Anthropic)
├── SOUL.md           # Primary agent identity (slot #1 in system prompt)
├── memories/         # Persistent memory (MEMORY.md, USER.md)
├── skills/           # Bundled + agent-created + hub-installed skills
├── cron/             # Scheduled jobs
├── sessions/         # Gateway session state
└── logs/             # agent.log, gateway.log, errors.log (secrets auto-redacted)

config.yaml vs. .env — quando uma configuração está definida em ambos, o config.yaml prevalece para configurações que não sejam secretas.4 A regra é: - Segredos (chaves API, tokens de bots, senhas) → .env - Todo o restante (modelo, backend do terminal, configurações de compactação, limites de memória, toolsets) → config.yaml

Os segredos podem ser referenciados no config.yaml usando interpolação no estilo do shell:4

auxiliary:
  vision:
    api_key: ${GOOGLE_API_KEY}
    base_url: ${CUSTOM_VISION_URL}
  delegation:
    api_key: ${DELEGATION_KEY}

Gerenciamento da configuração

hermes config                # View current configuration
hermes config show           # Same as above
hermes config edit           # Open config.yaml in your editor
hermes config set KEY VAL    # Set a specific value
hermes config get KEY        # Print a single value (v0.19.0+)
hermes config unset KEY      # Remove a key so the default applies again (v0.19.0+)
hermes config path           # Print the config file path
hermes config env-path       # Print the .env file path

Exemplos:4

hermes config set model anthropic/claude-opus-4
hermes config set terminal.backend docker
hermes config set OPENROUTER_API_KEY sk-or-...   # Saves to .env

hermes config check e hermes config migrate são os comandos que você deve executar após cada hermes update — eles detectam novas opções de configuração que ainda não estão no seu arquivo.6

Precedência da configuração

O Hermes carrega a configuração de várias fontes. Quando várias fontes definem o mesmo valor, prevalece a fonte de maior prioridade:4

  1. Argumentos de CLI — hermes chat --model anthropic/claude-sonnet-4 (substituição por execução)
  2. Variáveis de ambiente — aplicadas na inicialização do processo
  3. config.yaml — o arquivo principal de configurações
  4. .env — somente segredos
  5. Valores padrão integrados — aplicados quando nenhuma outra fonte define um valor

As flags de CLI sempre prevalecem naquela execução específica. O config.yaml é a fonte da verdade de longo prazo.

Localização (v0.13.0+)

A v0.13.0 adicionou 7 localidades para mensagens de CLI e do gateway: chinês (simplificado), japonês, alemão, espanhol, francês, ucraniano e turco.18 A v0.14.0 traduz todos os comandos do gateway e o dashboard web, adiciona mais 8 localidades e eleva o total para 16.19 No momento, a documentação está disponível em zh-Hans apenas. A localidade é determinada pelas variáveis de ambiente LC_ALL / LANG ou por uma chave locale: explícita no config.yaml. O inglês continua sendo o padrão e a fonte da verdade para qualquer texto que ainda não tenha sido contemplado por uma tradução.

Profiles — várias instâncias isoladas do Hermes

Os profiles permitem que você tenha várias instâncias isoladas do Hermes, cada uma com sua própria configuração, sessões, skills, memória e PID do gateway. É assim que você executa um “Hermes de trabalho” e um “Hermes pessoal” lado a lado, sem que um tenha acesso ao estado do outro.6

hermes profile list
hermes profile create work --clone                  # Clone from current profile
hermes profile use work                             # Set sticky default
hermes profile alias work --name h-work             # Create wrapper script
hermes profile export work -o work-backup.tar.gz
hermes profile import work-backup.tar.gz --name restored
hermes -p work chat -q "Hello from work profile"    # One-off without switching

Cada profile recebe seu próprio HERMES_HOME (~/.hermes-<name>/ por padrão), permitindo que vários profiles executem o gateway simultaneamente sem interferir uns nos outros.63

hermes logs — Consulta estruturada de logs

Kanban multiagente (v0.13.0+)

A v0.13.0 transforma a colaboração multiagente em um recurso fundamental: um quadro Kanban durável que acompanha tarefas, status e a identidade dos workers entre diferentes agentes e reinicializações.18 É esse quadro que permite que um conjunto de workers do Hermes realmente conclua o trabalho, em vez de ficar travado em transferências interrompidas.

Mecanismo O que faz
Heartbeats Cada worker envia pulsos enquanto é responsável por uma tarefa. Quando um heartbeat não é recebido, o worker é marcado como suspeito e a tarefa é liberada para ser retomada.
Retomada Outro worker pode assumir uma tarefa abandonada, com acesso ao estado completo da tarefa e aos resultados parciais anteriores.
Detecção de zumbis Workers que são encerrados sem marcar uma tarefa como concluída ficam automaticamente impedidos de assumir novos trabalhos, evitando que o conjunto acumule identidades inativas.
Barreira contra alucinações Se um resultado não passar pela barreira, a tarefa retorna ao quadro com o motivo registrado, em vez de ser marcada como concluída.
max_retries por tarefa Substitui o limite padrão de novas tentativas em uma tarefa que você sabe ser instável.
Quadros para vários projetos Uma única pasta inicial do Hermes pode hospedar vários quadros independentes.

O quadro Kanban combina naturalmente com /goal (loop Ralph com objetivo bloqueado) para definir o objetivo e com a ferramenta delegate_task existente para a semântica de criação. O resultado é um padrão de conjunto de agentes em que todos compartilham uma única fonte da verdade sobre o que fazer em seguida, quem está trabalhando em cada tarefa e o que está travado.

Sistema de skills

Skills são documentos de conhecimento sob demanda que o agente pode carregar quando necessário. Elas seguem um padrão de divulgação progressiva para minimizar o uso de tokens e são compatíveis com o padrão aberto agentskills.io.11

Todas as skills ficam em ~/.hermes/skills/ — a pasta principal e fonte da verdade. Em uma instalação nova, as skills incluídas são copiadas do repositório. Skills instaladas pelo hub e criadas pelo agente também ficam aqui.11

Divulgação progressiva

Level 0: skills_list()           → [{name, description, category}, ...]   (~3k tokens)
Level 1: skill_view(name)        → Full content + metadata                 (varies)
Level 2: skill_view(name, path)  → Specific reference file                 (varies)

O agente só carrega o conteúdo completo da skill quando realmente precisa dele.11

---
name: my-skill
description: Brief description of what this skill does
version: 1.0.0
platforms: [macos, linux]      # Optional — restrict to OS platforms
metadata:
  hermes:
    tags: [python, automation]
    category: devops
    fallback_for_toolsets: [web]     # Conditional activation
    requires_toolsets: [terminal]    # Conditional activation
    config:                          # Config.yaml settings
      - key: my.setting
        description: "What this controls"
        default: "value"
        prompt: "Prompt for setup"
---

Ativação condicional

As skills podem ser exibidas ou ocultadas de acordo com as ferramentas disponíveis. Isso é especialmente útil para skills de fallback — alternativas gratuitas ou locais que só devem aparecer quando uma ferramenta premium não estiver disponível:11

Campo Comportamento
fallback_for_toolsets A skill fica oculta quando os toolsets listados estão disponíveis
fallback_for_tools Igual ao anterior, mas verifica ferramentas individuais
requires_toolsets A skill fica oculta quando os toolsets listados não estão disponíveis
requires_tools Igual ao anterior, mas verifica ferramentas individuais

Exemplo: a skill integrada duckduckgo-search usa fallback_for_toolsets: [web]. Quando você tem FIRECRAWL_API_KEY configurada, o toolset da web fica disponível e o agente usa web_search — a skill do DuckDuckGo permanece oculta. Sem a chave API, a skill do DuckDuckGo aparece automaticamente como fallback.11

Memória persistente

Hermes tem uma memória limitada e selecionada que persiste entre as sessões. Dois arquivos compõem a memória do agente, ambos armazenados em ~/.hermes/memories/:12

Arquivo Finalidade Limite de caracteres
MEMORY.md Notas pessoais do agente — informações do ambiente, convenções e aprendizados 2.200 caracteres (~800 tokens)
USER.md Perfil do usuário — preferências, estilo de comunicação e expectativas 1.375 caracteres (~500 tokens)

Ambos são inseridos no prompt do sistema como um snapshot imutável no início da sessão. O agente gerencia a própria memória por meio da ferramenta memory — add, replace ou remove.12

Padrão de snapshot imutável: a inserção no prompt do sistema é capturada uma única vez no início da sessão e nunca muda durante a sessão. Isso é intencional — preserva o cache de prefixo do LLM para melhorar o desempenho. As alterações feitas durante uma sessão são salvas imediatamente no disco, mas só aparecem no prompt do sistema na sessão seguinte.12

O que salvar

Salve estas informações (o agente faz isso proativamente):12 - Preferências do usuário: “Prefiro TypeScript a JavaScript” → user - Informações do ambiente: “Este servidor executa Debian 12 com PostgreSQL 16” → memory - Correções: “Não use sudo nos comandos do Docker; o usuário está no grupo docker” → memory - Convenções: “O projeto usa tabulações, largura de linha de 120 caracteres e docstrings no estilo Google” → memory - Trabalho concluído: “O banco de dados foi migrado do MySQL para o PostgreSQL em 15 de janeiro de 2026” → memory

Não salve estas informações:12 - Informações triviais ou óbvias - Informações fáceis de descobrir novamente - Dumps de dados brutos (grandes demais para a memória) - Informações efêmeras específicas da sessão - Informações que já estão nos arquivos de contexto

Além de MEMORY.md e USER.md, o agente pode pesquisar conversas anteriores usando a ferramenta session_search. Todas as sessões do CLI e de plataformas de mensagens são armazenadas no SQLite (~/.hermes/state.db), com pesquisa de texto completo via FTS5. As consultas retornam conversas anteriores relevantes, resumidas pelo Gemini Flash.12

Retomada automática de sessões (v0.13.0+)

A v0.13.0 permite recuperar o trabalho após uma interrupção durante a execução do agente. Checkpoints v2 (v0.13.0+)

Na v0.13.0, a persistência de estado foi reescrita com um design de armazenamento único, limpeza real, limites de segurança para o disco e nenhum repositório paralelo órfão.18 O sistema de checkpoint anterior acumulava estados no disco em profiles executados por longos períodos; o armazenamento v2 impõe um limite rígido ao espaço local ocupado pelos checkpoints e elimina os registros duplicados que causavam esse crescimento. Nenhuma alteração nas configurações do usuário é necessária; a próxima gravação de checkpoint usará o caminho v2.

Personalidade e SOUL.md

SOUL.md é a identidade principal de uma instância do Hermes. Ele ocupa a posição nº 1 no prompt do sistema, substituindo a identidade padrão definida diretamente no código.13

Hermes cria automaticamente um SOUL.md padrão em ~/.hermes/SOUL.md (ou em $HERMES_HOME/SOUL.md para profiles personalizados). Arquivos existentes do usuário nunca são sobrescritos. Hermes carrega o SOUL.md somente de HERMES_HOME — ele não procura no diretório de trabalho atual. Isso mantém a personalidade consistente entre projetos.13

O que incluir no SOUL.md

Use-o para definir orientações duradouras de voz e personalidade:13 - tom - estilo de comunicação - nível de objetividade - estilo padrão de interação - o que evitar em termos de estilo - como Hermes deve lidar com incertezas, discordâncias e ambiguidades

Use-o menos para:13 - instruções pontuais de um projeto - caminhos de arquivos - convenções do repositório - detalhes temporários do fluxo de trabalho

Essas informações devem ficar em AGENTS.md, não em SOUL.md.

SOUL.md vs. AGENTS.md

Esta é a distinção mais importante no gerenciamento da identidade do Hermes:13

SOUL.md — identidade, tom, estilo, padrões de comunicação e comportamento relacionado à personalidade.

AGENTS.md — arquitetura do projeto, convenções de código, preferências de ferramentas, fluxos de trabalho específicos do repositório, comandos, portas, caminhos e observações sobre implantação.

Uma regra útil: se algo deve acompanhar você em todos os lugares, deve ficar em SOUL.md. Se pertence a um projeto, deve ficar em AGENTS.md.13

Como funciona

O gateway é ativado separadamente para cada ferramenta por meio de um novo campo de configuração use_gateway. Caso contrário, sua chave API direta (se houver) será usada.

# config.yaml — per-tool gateway opt-in
tools:
  web_search:
    provider: firecrawl
    use_gateway: true          # route via Nous Portal subscription
  image_generation:
    provider: fal
    use_gateway: true

Precedência em tempo de execução: quando o gateway está disponível e uma ferramenta tem use_gateway: true, o Hermes prioriza o gateway mesmo que você também tenha configurado uma chave API direta. Isso é relevante para a cobrança — as chamadas do gateway consomem sua assinatura do Portal, não o saldo da sua chave API direta.

Como as mensagens fluem

De acordo com a documentação de arquitetura do projeto original:3

Platform event → Adapter.on_message() → MessageEvent
  → GatewayRunner._handle_message()
    → authorize user
    → resolve session key
    → create AIAgent with session history
    → AIAgent.run_conversation()
    → deliver response back through adapter

Todas as plataformas de mensagens passam pelo mesmo loop de conversa AIAgent usado pelo CLI. É por isso que os comandos de barra funcionam da mesma forma nos dois ambientes e que uma tarefa cron agendada no Telegram pode entregar o resultado no Discord — a diferença entre as plataformas existe apenas nas extremidades.3

A v0.19.0 adiciona roteamento de mensagens baseado em profiles e entrega durável. Um único gateway multiplexado que compartilha um token de bot pode encaminhar guildas, canais ou threads específicos para diferentes profiles — cada um com configurações, skills, memória e segredos totalmente isolados — com uma substituição por GATEWAY_MULTIPLEX_PROFILES. Além disso, uma série de melhorias de robustez impede que um profile configurado incorretamente derrube todo o gateway. Internamente, o índice de roteamento foi transferido para state.db (sessions.json agora é um espelho legado opcional), e as respostas finais são registradas em um ledger durável de obrigações de entrega antes e depois do envio pela plataforma — se uma resposta concluída for interrompida por uma falha do gateway, ela será reenviada na próxima inicialização em vez de ser perdida silenciosamente.23

Compressão de contexto

O Hermes compacta automaticamente conversas longas para mantê-las dentro da janela de contexto do seu modelo. O sumarizador de compactação faz uma chamada LLM separada — você pode direcioná-la para qualquer provider ou endpoint.4

compression:
  enabled: true
  threshold: 0.50                           # Compress at this % of context limit
  target_ratio: 0.20                        # Fraction to preserve as recent tail
  protect_last_n: 20                        # Min recent messages to keep uncompressed
  summary_model: "google/gemini-3-flash-preview"
  summary_provider: "auto"                  # "auto", "openrouter", "nous", "codex", "main", etc.
  summary_base_url: null                    # Custom OpenAI-compatible endpoint

Opções de provider:4

summary_provider summary_base_url Resultado
auto (padrão) não definido Detecta automaticamente o melhor provider disponível
nous / openrouter / etc. não definido Força esse provider e usa sua autenticação
qualquer valor definido Usa o endpoint personalizado diretamente (o provider é ignorado)

summary_model precisa aceitar um contexto pelo menos tão longo quanto o do seu modelo principal, pois recebe toda a seção intermediária da conversa para compactação.4

Solução de problemas

“Nenhum provedor de inferência configurado. Execute ‘hermes model’ para escolher um provedor e um modelo”

O primeiro erro que toda instalação nova encontra: o Hermes ainda não tem um provedor definido. A mensagem significa exatamente o que diz — nenhum dos três métodos de autenticação produziu um provedor utilizável. Execute:

hermes model

O seletor interativo apresenta todos os provedores compatíveis, incluindo os fluxos de código de dispositivo OAuth (Nous Portal, GitHub Copilot, Anthropic, OpenAI Codex) e endpoints personalizados para servidores auto-hospedados. Se você esperava que um provedor já estivesse configurado, hermes doctor mostra quais credenciais o Hermes realmente consegue encontrar; as causas mais comuns são uma chave API definida no lugar errado (ela deve ficar no .env ou ser configurada com hermes config set, não no seu profile do shell), uma credencial OAuth expirada em ~/.hermes/auth.json ou um endpoint personalizado no config.yaml que perdeu seu base_url. Os métodos de autenticação são abordados em detalhes em Autenticação e provedores.27

“Chave API não definida”

Execute hermes model para configurar seu provedor de forma interativa ou hermes config set OPENROUTER_API_KEY your_key. O comando hermes doctor informará exatamente quais chaves estão faltando.7

“Limite de contexto: 2048 tokens” na inicialização (modelos locais)

O Hermes detecta automaticamente o tamanho do contexto pelo endpoint /v1/models do seu servidor, mas muitos servidores locais informam valores padrão baixos. Defina-o explicitamente no config.yaml:2

model:
  default: your-model
  provider: custom
  base_url: http://localhost:11434/v1
  context_length: 32768

As chamadas de ferramentas aparecem como texto em vez de serem executadas

Seu servidor não está com a chamada de ferramentas habilitada ou o modelo não oferece suporte a ela por meio da implementação do servidor.2

Servidor Correção
llama.cpp Adicione --jinja ao comando de inicialização
vLLM Adicione --enable-auto-tool-choice --tool-call-parser hermes
SGLang Adicione --tool-call-parser qwen (ou o parser apropriado)
Ollama A chamada de ferramentas é habilitada por padrão — verifique se seu modelo oferece suporte com ollama show <model>
LM Studio Atualize para a versão 0.3.6 ou posterior e use um modelo com suporte nativo a ferramentas

As respostas são interrompidas no meio de uma frase

Há duas causas possíveis:2

  1. Limite de saída baixo (max_tokens) no servidor — o padrão do SGLang é 128 tokens por resposta. Defina --default-max-tokens no servidor ou configure model.max_tokens no config.yaml.
  2. Esgotamento do contexto — o modelo preencheu toda a janela de contexto. Aumente model.context_length ou habilite a compactação de contexto no Hermes.

“Conexão recusada” do WSL2 para um servidor de modelos hospedado no Windows

O WSL2 usa um adaptador de rede virtual com sua própria sub-rede — localhost dentro do WSL2 se refere à VM Linux, não ao host Windows. Há duas opções:2

Rede espelhada (Windows 11 22H2 ou posterior): edite %USERPROFILE%\.wslconfig:

[wsl2]
networkingMode=mirrored

Depois, execute wsl --shutdown e reinicie. Agora, localhost funciona nas duas direções.

Alternativa com o IP do host (versões anteriores do Windows): obtenha o IP do host Windows dentro do WSL2 e use-o no lugar de localhost:

ip route show | grep -i default | awk '{ print $3 }'
# Use that IP as the base_url host

Você também precisa configurar o servidor de modelos para escutar em 0.0.0.0, não em 127.0.0.1 — defina OLLAMA_HOST=0.0.0.0 para o Ollama, adicione --host 0.0.0.0 ao llama-server/SGLang ou habilite “Serve on Network” no LM Studio.2

Perguntas frequentes

Qual é a diferença entre o Hermes Agent e o Claude Code?

O Claude Code é o CLI oficial da Anthropic, limitado aos modelos da Anthropic. O Hermes Agent é um framework de agente de código aberto da Nous Research que funciona com qualquer provedor compatível com a OpenAI — Nous Portal, OpenRouter, Anthropic, GitHub Copilot, z.ai, Kimi, MiniMax, DeepSeek, Hugging Face, Google ou seu próprio endpoint auto-hospedado.12 O Hermes também inclui um gateway de mensagens para Telegram/Discord/Slack/WhatsApp/Signal, recurso que o Claude Code não oferece.

Posso usar o Hermes com uma chave API da Anthropic?

Sim. Há três formas:2

  1. Defina ANTHROPIC_API_KEY em ~/.hermes/.env e execute hermes chat --provider anthropic --model claude-sonnet-4-6
  2. Execute hermes model e selecione Anthropic — o Hermes usará o armazenamento de credenciais do Claude Code quando ele estiver disponível
  3. Defina manualmente um ANTHROPIC_TOKEN (setup-token ou token OAuth) como alternativa

A opção 2 é preferível se você já usa o Claude Code na mesma máquina — ela mantém renováveis as credenciais Claude que podem ser renovadas.

Como faço para trocar de provedor sem perder minha conversa?

Use /model provider:model dentro de uma sessão. O histórico da conversa, a memória e as skills são mantidos:9

/model zai:glm-5
/model openrouter:anthropic/claude-sonnet-4
/model custom:local:qwen-2.5

Configurei a Anthropic, mas visão/web/compactação não funcionam

Você está encontrando o fallback do modelo auxiliar. A visão, o resumo de conteúdo web, a compactação e outras tarefas secundárias usam um LLM auxiliar separado — por padrão, o Gemini Flash por meio da detecção automática (OpenRouter → Nous → Codex). Se nenhum deles estiver configurado e você tiver apenas a Anthropic, esses recursos perderão funcionalidade sem apresentar um erro.4

Correção: adicione uma OPENROUTER_API_KEY para as tarefas auxiliares ou reconfigure os slots auxiliares para usar seu provedor principal. Observe que a compactação de contexto fica em seu próprio bloco compression: de nível superior e aceita summary_provider, não auxiliary.compression.provider — o slot auxiliary.compression expõe apenas um timeout. Correção completa:

auxiliary:
  vision:      { provider: "main" }
  web_extract: { provider: "main" }

compression:
  summary_provider: "main"

Qual é a diferença entre SOUL.md e AGENTS.md?

SOUL.md define a identidade do seu agente — tom, estilo e padrões de comunicação. Ele fica em ~/.hermes/SOUL.md e acompanha você em todos os lugares. AGENTS.md é específico do projeto — arquitetura, convenções, comandos e caminhos — e fica no diretório do projeto.13 Se deve acompanhar você em todos os lugares, use SOUL.md. Se pertence a um projeto, use AGENTS.md.

Como executo várias instâncias do Hermes lado a lado?

Use profiles. Cada profile recebe seu próprio HERMES_HOME, suas próprias configurações, memória, sessões e PID do gateway:6

hermes profile create work --clone
hermes profile use work                 # Sticky default
hermes -p work chat -q "..."            # One-off without switching
hermes profile alias work --name h-work # Wrapper script

O Hermes oferece suporte a LLMs locais?

Sim, por meio de um endpoint personalizado. O Hermes funciona com qualquer servidor compatível com a OpenAI: Ollama, vLLM, SGLang, llama.cpp/llama-server, LM Studio, LocalAI, Jan ou um servidor próprio.2 Consulte Endpoints personalizados e auto-hospedados para ver a configuração de cada servidor.

Por que o banner de inicialização mostra menos ferramentas do que o guia diz que o Hermes possui?

O guia menciona 47 ferramentas/20 toolsets com base no registro de arquitetura upstream — essa é a contagem completa das ferramentas cujo código-fonte o Hermes inclui em todos os toolsets. Sua instalação em execução mostra um número menor no banner (a instalação de referência usada neste guia informa 28 ferramentas) porque o Hermes habilita apenas o conjunto padrão de toolsets na inicialização. Muitos toolsets são opcionais: adaptadores do gateway de mensagens, automação de navegador, conjuntos mais robustos de scraping e várias integrações especializadas precisam ser listados explicitamente em toolsets: no ~/.hermes/config.yaml antes de serem carregados. Total do registro = “o que está disponível se você habilitar”. Total do banner = “o que seu profile atual realmente carregou”. Use hermes tools --list para ver quais toolsets estão ativos e quais estão disponíveis, mas desabilitados. Ative ou desative toolsets individualmente durante a execução com /tools enable <name> e /tools disable <name> (a desativação reinicia a sessão para que o agente reconstrua seu manifesto de ferramentas com a nova estrutura).

Como o Hermes lida com o fallback de modelo quando meu provedor principal falha?

Configure um bloco fallback_model no config.yaml:2

fallback_model:
  provider: openrouter
  model: anthropic/claude-sonnet-4

Quando o provedor principal falha (limite de taxa, erro do servidor ou falha de autenticação), o Hermes troca para o fallback durante a sessão sem perder o histórico da conversa. Isso ocorre no máximo uma vez por sessão.

O agente pode aprimorar suas próprias skills com o tempo?

Sim — essa é a parte “autoaperfeiçoável” do Hermes Agent. O agente pode criar, atualizar e excluir skills por meio da ferramenta skill_manage. Quando descobre um fluxo de trabalho não trivial, ele salva a abordagem como uma skill para reutilização futura.11 O agente cria skills após tarefas complexas (mais de 5 chamadas de ferramentas), quando encontra erros e descobre o caminho que funciona, quando você corrige a abordagem adotada ou quando ele descobre um fluxo de trabalho não trivial.

Existe integração com IDE?

Sim — o Hermes pode ser executado como um servidor ACP (Agent Client Protocol) para VS Code, Zed e JetBrains:6

pip install -e '.[acp]'
hermes acp
