## Token, OAuth ou variável?

### CodeRabbit

```text

AUTENTICAÇÃO=GitHub App já instalada
CONFIGURAÇÃO=.coderabbit.yaml
```

### Codex GitHub Review

```text
TOKEN_NO_REPO=nenhum
AUTENTICAÇÃO=Codex Cloud + GitHub
REGRAS=AGENTS.md
ACIONAMENTO=@codex review
```

Não devemos colocar sua sessão OAuth, `auth.json`, token da conta ChatGPT ou API key em GitHub Secrets para isso. A integração oficial do Codex é habilitada nas configurações do Codex e depois trabalha diretamente nos PRs. O modo automático para todos os PRs também é ativado nas configurações do Codex, não por variável inventada no workflow. ([ChatGPT Learn][2])

## Lacuna real que localizei

O workflow existente chamado:

```text
PR auto-review (Codex + checklist)
```

tem nome de Codex, mas atualmente:

* ignora PR draft por causa de `!github.event.pull_request.draft`;
* executa checklist determinístico;
* executa Gemini consultivo;
* não contém um job real chamando o Codex.

Então são duas coisas diferentes:

```text
PR auto-review.yml
= checklist interno + Gemini

@codex review
= Codex oficial conectado ao GitHub
```

Não vou fingir que o workflow interno já era Codex porque o nome dizia “Codex”. O Codex real está sendo chamado pela integração oficial.
