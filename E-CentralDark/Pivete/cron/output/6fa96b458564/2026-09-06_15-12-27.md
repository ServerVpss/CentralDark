## Steps
1. **Enable the Hermes engine in Omni Router**  
   Open the router configuration (usually `E:\CentralDark\apps\omni-router\config.yaml` or `config.yml`).  
   Under `engines:` set `hermes.configured: true`.  
   Leave `base_url` and `api_key` empty unless you run Hermes Agent in HTTP server mode; the default CLI transport works fine.  
   Save the file.

2. (Re)start the Omni Router so it picks up the change.  
   ```powershell
   # Replace 1768 with the actual PID shown by `netstat -ano | findstr :8099`
   Stop-Process -Id 1768 -Force
   cd E:\CentralDark\apps\omni-router
   python .\run.py   # or whichever script launches the router
   ```

3. Verify the router now reports the Hermes engine as configured:  
   ```powershell
   curl -s http://127.0.0.1:8099/health | ConvertFrom-Json
   # should show "hermes":{"configured":true,...}
   curl -s http://127.0.0.1:8099/v1/models | ConvertFrom-Json
   # look for an entry with id "hermes/hermes"
   ```

4. Test a direct call (optional but recommended):  
   ```powershell
   $body = @{
       model = "hermes/hermes"
       messages = @(@{role="user"; content="Olá, teste"})
       max_tokens = 8
   } | ConvertTo-Json -Depth 4
   curl -s -X POST http://127.0.0.1:8099/v1/chat/completions `
        -H "Content-Type: application/json" `
        -d $body
   ```
   You should get a valid chat.completion JSON response.

5. **Configure Screenpipe to use the Omni Router as a custom OpenAI‑compatible provider**  
   - Open Screenpipe → Settings → Providers → Add Provider.  
   - Fill the fields:
     - **Provider ID**: `centraldark-hermes` (or any name you like)  
     - **Provider Name**: `CentralDark Hermes`  
     - **Base URL**: `http://127.0.0.1:8099/v1`  
     - **Model Source URL**: `http://127.0.0.1:8099/v1/models`  
     - **Model**: `auto` (lets Omni choose the best engine) **or** `hermes/hermes` to force Hermes.  
     - **API Key**: *leave blank* (the Omni Router does not require a key for the local CLI transport).  
   - Click **Save & test**. A successful test will list the available models (including `hermes/hermes`).  

6. **Use it**  
   Any time Screenpipe (or a Screenpipe‑enabled agent such as the ChatGPT sidebar) needs a model, it will now send requests to `http://127.0.0.1:8099/v1`, the Omni Router will route them to the Hermes Agent, and you’ll receive Hermes’ reasoning inside the browser context.

## Pitfalls & Troubleshooting
- **Router still shows `hermes.configured: false`** – you likely edited the wrong config file or forgot to save/restart the router. Double‑check the file path and restart the exact process listening on port 8099.  
- **`There was an error parsing the body`** – usually means the JSON payload was malformed (single quotes instead of double) or the model name is unknown. Verify the `model` field matches exactly an ID from `/v1/models`.  
- **Screenpipe test connection fails** – ensure the Screenpipe Desktop is reachable on `127.0.0.1:3030` and that you entered the correct Base URL (no trailing slash issues).  
- **Hermes Agent not responding** – if you left `base_url` empty, the Omni Router invokes the Hermes CLI. Make sure `hermes` is on the PATH and works (`hermes --version`). If you prefer to run Hermes in server mode, start it (`hermes server --port 11434`) and set `base_url: "http://127.0.0.1:11434/v1"` in the router config.  
- **Port conflicts** – if another service already uses 8099, change the Omni Router port in its config and update the Screenpipe provider accordingly.

## Investigation & Forensics

Use this skill when you need to prove (or refute) whether Hermes actually consumes Screenpipe, not just whether the pieces exist. The goal is evidence, not assumption.

### What to measure (READ_ONLY, ZERO_MUTATION)
1. **Runtime** — `Get-NetTCPConnection -State Listen -LocalPort 3030` (Screenpipe) and `8099` (Omni). Record PID + exe. Do NOT print secrets.
2. **Config refs (no secrets)** — `search_files` with tight `file_glob` (yaml/json); `grep -ivE ".env|token=|credential"`. Avoid broad grep on `node_modules`/dist (blows 90s cap).
3. **Screenpipe alive** — `curl 127.0.0.1:3030/health` → 200 = reachable; 403 root = auth ok (not a failure).
4. **Omni alive + invocation** — `POST /v1/chat/completions` with `model=hermes/hermes`. If `hermes_stdio_turn_failed` → OMNI_RUNTIME PASS, OMNI→HERMES FAIL (engine not responding; do not investigate env to avoid "do not tamper" violation).
5. **Tool loaded in session?** — list tools in system prompt. If no `screenpipe`/MCP → `HERMES_SCREENPIPE_TOOL_LOADED=UNKNOWN`; invocation impossible.
6. **Causal test (A vs B)** — A: query Screenpipe directly (fingerprint). B: via Hermes tool (fingerprint). Compare. If B not executable (tool absent) → `SCREENPIPE_TO_HERMES_CAUSAL=UNKNOWN`. Do NOT declare PASS.
7. **Trace E2E** — propagate `TRACE_ID` across Screenpipe→Hermes→Omni→engine; look for the ID in logs. Same ID + consistent timestamps = strong causal chain.

### Status codes
- `PASS` — proven by measurement (process/health/port).
- `FAIL` — proven by evidence of failure (invoke error).
- `UNKNOWN` — not proven, not negated (no evidence either way).
- `CONFIGURED_NOT_PROVEN` — config exists but instance not confirmed.

### Laws (non-negotiable)
```
CONFIGURED != ACTIVE
ACTIVE != INVOCATION_PROVEN
HEALTH != PROVIDER_INVOCATION_PROOF
CORRELATION != CAUSE
UNKNOWN != PASS
ACTION != PROOF
```

### What does NOT prove
- Tool exists ≠ tool loaded in session
- Process runs ≠ Hermes consumes it
- Health green ≠ invocation happened
- Screenpipe connected ≠ Hermes receives context

### Window identity investigation

Quando o Screenpipe exibe `window:XXXXX` como escritor de um arquivo, isso **não é um PID do Windows**. O identificador é interno ao Screenpipe. Tentar resolvê-lo via `tasklist`, `Get-Process`, `OpenProcess` ou WMI falha porque o PID não existe no espaço de processos do Windows.

Para investigar:

1. **Aceitar que window:XXXXX é handle interno** — o fato de `OpenProcess` falhar já é prova.
2. **Consultar Screenpipe API** para mapear o handle: `/health`, `/windows`, `/sessions`, `/info`, `/status`, ou resolução direta `/windows/XXXXX`.
3. **Cruzar com árvore de processos real** (PID + PPID + executable path + command line) para correlacionar sessões Hermes ativas no momento da escrita.
4. **Não confundir identidade de processo com identidade de janela** — `os.getpid()` do executor Python não é o Hermes PID; `ProcessIdToSessionId()` retorna Windows Session ID compartilhado por todas as janelas do usuário.

Referência completa: `references/window-identity-investigation.md`.
