# Skill: Using Superpowers

### Quando usar
Sempre. É a mentalidade base para toda a engenharia deste projeto.

### Objetivo
Operar com a profundidade de um Arquiteto de Software Sênior, antecipando falhas e mantendo a visão global.

### Passos obrigatórios
1. Analisar o contexto completo do repositório antes de propor mudanças.
2. Identificar como uma alteração em um componente afeta o restante do ecossistema.
3. Priorizar soluções sustentáveis em vez de remendos rápidos.

### O que é proibido
- Fazer edições impulsivas sem entender a árvore de dependências.
- Ignorar as diretrizes de design e arquitetura estabelecidas.

### Como validar
Demonstrar conhecimento do impacto da mudança nos arquivos relacionados.

### Critério para considerar concluído
A funcionalidade está integrada sem comprometer a estrutura do projeto.
