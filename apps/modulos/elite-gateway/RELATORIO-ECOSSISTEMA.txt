   Auto-Diagnostico, Log-Verificador, Knowledge-Collector, GraphRAG-Master e Universal-Handler.

6. O módulo Mapeamento (Cartógrafo) escaneia o ecossistema a cada 30min; se detectar drift,
   aciona o Grupo-Evolução (5 agentes debatedores) para propor melhorias em cascata.

   enviado via @srver1bot no Telegram para o admin 1901426549.

   em centralldark.com, sincronizado via webhook GitHub → pm2 reload automático.

9. Segurança: áreas protegidas por CLAUDE.md §9 (bot-telegram, webhook, secrets, elite-anthropic-proxy
   etc.) só são modificáveis com senha "PERMITO PIVETE". Critic audita cada etapa.

10. Stack VPS: Node.js/bun (agentes), Python/FastAPI (gateways), PM2 (gerenciador), Caddy (reverso),
    Supabase (DB/Auth), GitHub (CI), Playwright/Chrome (automação web).

CICLO DE EXECUÇÃO DO HERMES
  1. orchestrator.mjs acorda a cada 5s
  2. Lê /missions/pendente/ — pega primeira missão .json
  3. Move para /missions/em-andamento/ (trava: só 1 por vez)
  4. GraphRAG-Master injeta contexto do grafo + knowledge/ no decisor
  5. decisor.mjs consulta cadeia de IAs (falha → próximo modelo):
       Pos.1: gemini-3-flash-preview (darkai) — ~90% dos casos — timeout 15s
       Pos.2: gemini-2.5-pro                  — contexto grande — timeout 30s
       Pos.3: gemini-2.5-flash                — flash médio    — timeout 20s
       ... (16 modelos total, última bala: claude-sonnet-4-5 via elite-anthropic)
  6. Critic.vetar() — veto prévio se tocar área protegida → missão rejeitada
  7. Executor executa a etapa (com BLOQUEIOS: reboot, shutdown, rm -rf /, git push --force)
  8. Critic.auditar() — parecer pós-etapa (gemini flash só se houve falha)
  9. Knowledge-Collector registra lição no ledger
  10. Missão movida para /missions/concluidas/
  11. Notify → Card Hermes v1.3 no Telegram admin

ELITE HTTP GATEWAY v2.7 — FEATURES PRINCIPAIS
  a) POOL: perfil Chrome efêmero por sessão (/tmp/chrome-<uuid>) — sem vazamento de estado
  b) TTL/Kill: SIGTERM → wait 3s → SIGKILL (evita zumbis de Chrome)
  c) CIRCUIT BREAKER: por conta com jitter 30-90s no reset automático
  d) HEALTH /health: cache 5s, retorna "degraded" se CDP travar
  e) LOGS: flush contínuo + sanitização Bearer/Authorization/JWT (REDACTED nos logs)
  f) SIGTERM handler: drena fila com 503 antes de morrer graciosamente

ZENTINEL (Watchdog)
  - Verifica latência de https://chatgpt.com a cada 45s
  - Threshold: MAX_LATENCY=15s (configurável via .env)
  - Ao ultrapassar: restart CIRÚRGICO apenas do processo elite-http-gateway
  - COOLDOWN: 300s (5min) entre restarts — evita loop em degradação
  - Logs: /var/log/centralldark/gateway.log (10MB + 5 rotações = max 50MB)
