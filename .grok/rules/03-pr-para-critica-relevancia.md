# REGRA — PR para crítica de relevância (Pivete · 2026-07-16)

Quando o Pivete pedir **abrir PR** para revisores **criticarem** uma ideia/funcionalidade:

1. Abrir PR (branch limpa quando a main VPS estiver divergente).
2. Corpo do PR deve pedir explicitamente:
   - relevância real (Grok / infra / castelo / auto-evolução)
   - melhorar o que **já existe** (sem V1/V2/V3 paralelo)
   - não destruir legado
   - merge só após crítica
3. Não tratar push de branch como “já aprovado”.
4. Não auto-merge sem ordem.
5. Registrar o link do PR (card Telegram + APRENDIZADOS se for marco).

Isto **não** libera deploy/restart/secrets — só o fluxo de **revisão**.
