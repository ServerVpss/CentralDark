# Constituição Oficial do Arsenal Central Dark

> versão inicial consolidada a partir da conversa de 2026-07-07

## 1. Princípio soberano
A Central Dark não deve depender de uma IA específica. Ela deve obedecer a um **arsenal estrutural por papéis**, onde o melhor modelo disponível ocupa o papel adequado conforme capacidade, custo, disponibilidade, segurança e contexto.

## 2. Regra-mãe
**A IA mais forte não executa tudo. Ela orquestra.**
- Modelo forte = planeja, raciocina, decide, revisa, audita, valida.
- Modelo intermediário = implementa, itera, constrói, adapta.
- Modelo barato/local = trabalho braçal, transformação repetitiva, massa, suporte mecânico.

## 3. Sistema oficial 10-80-10
- **10% Planejamento**: arquitetura, abordagem, restrições, estratégia.
- **80% Execução**: implementação, iteração, produção de artefatos e automação.
- **10% Validação**: revisão final, coerência estrutural, segurança, correção.

## 4. Fórmula de economia
Se:
- `C_top` = custo do modelo premium
- `C_exec` = custo do executor econômico

Então:

`C_total = 0.10*C_top + 0.80*C_exec + 0.10*C_top`

Logo:

`C_total = 0.20*C_top + 0.80*C_exec`

Se `C_exec = 0.10*C_top`, então:

`C_total = 0.28*C_top`

Economia relativa versus “fazer tudo no topo”:

`Economia = 1 - 0.28 = 0.72 = 72%`

## 5. Política oficial de esforço
- **Medium** = padrão.
- **High** = somente quando Medium não fecha.
- **Extra High** = exceção.

## 6. Política oficial de contexto
Chat longo custa caro. Portanto:
- toda sessão longa deve gerar handoff;
- toda retomada deve começar leve;
- o contexto persistente deve viver em artefatos;
- o histórico bruto não deve ser a única memória operacional do sistema.

## 7. Estrutura oficial por papéis
### Papéis centrais
- Arquiteto Principal
- Orquestrador
- Executor Premium
- Executor Econômico
- Executor Local
- Validador Final
- Auditor de Segurança
- Sintetizador
- Pesquisador
- Roteador de Modelos
- Operador de MCP
- Guardião de Contexto / Handoff

### Regra de substituição
O nome do modelo não importa. Importa o papel.
Se amanhã existir modelo melhor que o atual:
- ele assume o papel correspondente;
- o arsenal permanece;
- a arquitetura não quebra.

## 8. Papel do status e do admin
### `status.centralldark.com`
Função: cockpit operacional diário.

### Painel admin
Função: quartel-general definitivo.

## 9. Doutrina de artefatos
Tudo que for importante deve virar artefato persistente.
Artefatos prioritários:
- `ARSENAL_MASTER.md`
- `ROUTING_POLICY.md`
- `HANDOFF_TEMPLATE.md`
- `SESSION_PROTOCOL.md`
- `TASK_CLASSIFIER.md`
- `MCP_CATALOG.md`
- `QUALITY_GATES.md`
- `PROJECT_STATE.md`
- `COST_POLICY.md`

## 10. Regra de continuidade
Toda IA na cadeia deve respeitar o que estiver definido no Arsenal Master.
A autoridade não é o nome do modelo; a autoridade é a política do arsenal.
