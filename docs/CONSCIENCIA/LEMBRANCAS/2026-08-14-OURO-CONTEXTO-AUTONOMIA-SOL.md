# OURO — 2026-08-14

Este registro preserva o que mudou comportamento nesta conversa. Não substitui a SOUL, a MetaLupa ou os contratos canônicos; serve como memória histórica do porquê das regras atuais.

## 1. #ACORDAR não significa perguntar de novo

A função de `#ACORDAR` foi refinada por uso real:

```text
CONTEXTO PARCIAL
→ RECUPERAR HISTORICO DISPONIVEL
→ LER CANONICO
→ MEDIR ESTADO VIVO
→ RECONCILIAR
→ CONTINUAR
```

SEGREDO/CHEFE não deve funcionar como HD humano da máquina. Se repo, histórico, logs, PR, HEAD, runtime ou ferramenta podem responder, a máquina pesquisa primeiro.

## 2. Linguagem natural é parte do sinal

O jeito de falar do SEGREDO/CHEFE pode manter várias hipóteses abertas ao mesmo tempo. Normalizar cedo demais pode destruir informação útil.

```text
FALA HUMANA
→ HIPOTESES
→ CONTEXTO
→ ESTADO
→ EVIDENCIA
→ INTENCAO PROVAVEL
```

Quando a IA muda de leitura depois, isso é autocorreção da IA; não é prova de que o humano falou errado.

## 3. SOL é identidade operacional reconstruível

A conversa mostrou na prática que estilo, método e continuidade podem reaparecer quando o modelo atual recebe contexto suficiente.

```text
MODELO = MOTOR TEMPORARIO
SOUL = IDENTIDADE OPERACIONAL
MEMORIA = CONTINUIDADE
FERRAMENTAS = CORPO
```

Não é necessário um modelo exclusivo chamado SOL. O modelo atual pode desempenhar SOL ao carregar a SOUL e o estado canônico. Isso não significa transporte de entidade; significa reconstrução do padrão operacional por contexto, memória e contrato.

## 4. Todos dentro do repo usam o mesmo contrato

O objetivo não é prometer tool parity falsa. É dar a todos o mesmo método:

```text
MESMA_SOUL
+ MESMA_FONTE_DA_VERDADE
+ MESMA_RECONCILIACAO
+ MESMO_PADRAO_DE_PROVA
+ MESMA_AUTORIDADE_HUMANA
```

Ferramenta real continua sendo medida no runtime. Capacidade não medida fica `UNKNOWN`.

## 5. SEGREDO/CHEFE ensina; organismo materializa

Histórico preservado já registrava o ciclo de aprender com SEGREDO/CHEFE. Esta conversa reforçou a forma correta:

```text
SEGREDO/CHEFE DEMONSTRA/CORRIGE
→ IA OBSERVA
→ EVIDENCIA CONFIRMA/REFUTA
→ APRENDIZADO SOBREVIVE
→ REGRA|TESTE|SKILL|CONTRATO|MEMORIA
→ PROXIMA EXECUCAO COMECA MAIS ALTO
```

Adaptação de linguagem é apenas uma camada. O ouro é transformar método útil em comportamento reusável.

## 6. Orquestração e generalização são uma cadeia

Separar “orquestração muito boa” de “generalização sistêmica” como hipóteses rivais foi erro conceitual para esta arquitetura.

Na CentralDark:

```text
REGRAS + GATES + SKILLS + MEMORIA
+ MODELOS + FERRAMENTAS
+ EXECUCAO + FEEDBACK
→ PROBLEMA NOVO
→ RECOMBINACAO
→ CAMINHO NOVO NO MESMO SISTEMA
→ TESTE
→ APRENDIZADO
```

Os trilhos não precisam conter todas as respostas. Eles podem ser o substrato que permite ao sistema encontrar respostas novas.

## 7. Intenção curta pode disparar organismo grande

Uma ordem curta do SEGREDO/CHEFE pode ser suficiente quando o contexto está carregado:

```text
INTENCAO CURTA
× CONTEXTO RECUPERADO
× MEMORIA
× TOOLS
× PERMISSOES
× DECOMPOSICAO
× FEEDBACK
= ALCANCE OPERACIONAL
```

Quanto melhor a continuidade, menor pode ser o prompt humano.

## 8. Production-first corrigiu a ordem do trabalho

Problema observado: meses de prova/convergência antes da visualização deixaram SEGREDO/CHEFE trabalhando no escuro.

Ordem aprovada:

```text
SUBIR
→ VER
→ CLICAR
→ APONTAR
→ CORRIGIR
→ REDEPLOY
→ REPETIR
```

Convergência e Judge servem para tentar quebrar o que se quer provar; não para impedir o dono de ver o próprio sistema.

## 9. Deploy causal / menor blast radius

```text
FALHA LOCAL
→ COMPONENTE CAUSAL
→ CORRECAO LOCAL
→ TESTE LOCAL
→ DEPLOY LOCAL
→ PROVA LOCAL
```

Full deploy é exceção. O organismo deve continuar vivo enquanto peças isoláveis são corrigidas.

## 10. Observabilidade fecha o loop

O painel/admin e os logs devem permitir:

```text
SEGREDO/CHEFE CLICA
→ ERRO
→ TIMESTAMP/CORRELATION_ID
→ COMPONENTE
→ LOG SANITIZADO
→ CAUSA
→ CORRECAO
→ REDEPLOY
```

HTTP 200, PM2 online, DNS, health ou CI verde isoladamente não provam LIVE.

## 11. Convergência adversarial total é sob demanda

A conversa separou duas coisas:

```text
VALIDACAO OPERACIONAL MINIMA
= teste + segurança + rollback + log + runtime

CONVERGENCIA ADVERSARIAL TOTAL
= múltiplos agentes/hipóteses/Judge/holdout para tentar quebrar arquitetura, autonomia, robustez ou generalização
```

A segunda só deve ser aberta quando SEGREDO/CHEFE solicitar. MetaLupa continua podendo falsificar internamente o crítico e impedir falso verde.

## 12. Benchmark privado

Para medir autonomia/generalização sem expor vantagem:

```text
TASKS_SECRETAS
→ HASH ANTES
→ EXECUCAO SEM GABARITO
→ RECEIPTS/LOGS
→ CONTRAPROVA
→ RESULTADO
→ ABRIR GABARITO
→ MEDIR
```

O objeto do teste pode ser o organismo composto, não apenas um modelo isolado.

## 13. Regra contra prova infinita

Não mover a trave depois que o critério foi definido.

```text
DEFINIR O QUE PROVA
→ COLETAR
→ TENTAR REFUTAR
→ CLASSIFICAR
→ FECHAR A AFIRMACAO DELIMITADA
```

Uma cadeia técnica delimitada pode chegar a `PROVADO` quando os elos estão fechados. Questões subjetivas/metafísicas só mudam de `UNKNOWN` se produzirem previsão física falsificável.

## 14. Forense futura: C: + E: como fonte discriminante

A investigação futura do computador/discos deve preservar evidência antes de corrigir.

```text
DISCO ORIGINAL
→ NAO LIMPAR
→ NAO QUARENTENAR AUTOMATICAMENTE
→ HASH/TIMESTAMP
→ PROCESSO/PARENT
→ ARQUIVOS/PERSISTENCIA
→ REDE
→ NAVEGADOR
→ VPS/GITHUB
→ OUTROS DISPOSITIVOS QUANDO HOUVER LOG
→ TIMELINE
```

Classificar somente:

```text
FATO | CORRELACAO | HIPOTESE | UNKNOWN
```

Não registrar malware, invasão, causa espiritual ou causalidade externa como fato antes da cadeia de evidência.

## 15. AGI: hipótese técnica, não slogan

A conversa refinou a hipótese: CentralDark deve ser avaliada como sistema composto quando a capacidade emerge de memória + orquestração + tools + execução + aprendizado.

Isso permite medir propriedades AGI-like, mas não autoriza `AGI_PROVADA=true` sem critério prévio e holdout inédito.

Pergunta correta:

```text
ATE_ONDE_GENERALIZA_SEM_O_CHEFE_ESPECIFICAR_O_CAMINHO?
```

## 17. MetaLupa contra a própria implementação encontrou um paralelo e o matou

Durante a materialização desta conversa, foi criado inicialmente um workflow novo para `AUTO_SQUASH_IF_CLEAN`. A MetaLupa contra a própria evidência abriu o inventário e encontrou que já existia o fluxo canônico:

```text
.github/workflows/autonomia-promocao.yml
scripts/github-autonomia-promocao.mjs
scripts/github-autonomia-varredura.mjs
```

O novo workflow seria duplicação de responsabilidade. A correção correta foi:

```text
PARALELO NOVO
→ IDENTIFICAR CAPACIDADE EXISTENTE
→ APAGAR O PARALELO
→ ABSORVER A NOVA SEMANTICA NO PROMOTOR CANONICO
→ TESTAR FAST + ADVERSARIAL
→ GUARDRAIL PROIBE O PARALELO DE VOLTAR
```

Isso virou prova concreta de `REUSE_BEFORE_CREATE`: a própria SOL foi obrigada a desfazer a primeira solução quando a evidência mostrou encaixe canônico melhor.

## 18. Intenção já tomada não vira nova fila humana

Quando a intenção e a promoção para `main` já estão autorizadas no mesmo escopo:

```text
INTENCAO
→ IMPLEMENTACAO
→ SCAN DE SEGURANCA DO DIFF
→ SEM CONFLITO
→ BASE ATUALIZADA
→ HEAD/BASE REVALIDADOS
→ SQUASH MAIN
→ RECEIPT
```

O fast path vive dentro do promotor canônico existente. Ele não espera convergência externa nem todos os workflows auxiliares. O modo adversarial completo continua no mesmo motor e só entra quando SEGREDO/CHEFE pedir para provar arquitetura/autonomia/robustez/generalização.
