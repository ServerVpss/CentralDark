## Princípio gerador

O salto é transformar os cinco princípios vivos numa **lei transversal de preenchimento de lacunas**:

> Toda brecha encontrada deve primeiro tentar ser preenchida por capacidade existente;
> se houver caminho repetível, vira determinístico;
> se houver conhecimento novo, vira memória;
> se houver nova capacidade, ela entra como braço do mesmo corpo;
> se nada provar o efeito, fica UNKNOWN.

## Domínios de aplicação

Cada domínio segue a mesma lei — brecha → classificar → reutilizar → menor delta → provar → aprender:

| Domínio | Regra |
|---|---|
| 🧠 Cognição/modelos | MODEL_CHANGE=ENGINE_SWAP, não identidade nova |
| 🦾 MCP/ferramentas | Ferramenta nova é capacidade do mesmo corpo; evolui a existente antes de criar outra |
| 🤖 Agentes/subagentes | Trabalho divisível vira paralelismo; resultado volta ao mesmo owner |
| 💾 Memória | DISCOVERY_WITH_REUSE_VALUE → PERSIST; chat não é memória final |
| 🌐 Rede/rotas | Uma aresta cair não condena o host; procura outra aresta viva |
| 🔗 Bindings | IP, porta, path, hostname, token, provider, modelo são mutáveis; remede o cone, não redesenha |
| ⏱️ Scheduler/cron | Tarefa repetível vira relógio determinístico, sem segundo relógio |
| 📡 Webhook/eventos | Brecha reativa vira trigger → dispatcher existente → capability |
| 🧪 Prova/testes | BUG_FIXED_ONCE → TEST; PATH_PROVEN → REPLAY |
| 🩺 Observabilidade | Coisa importante mas invisível ganha sensor no heartbeat existente, não segundo coração |
| 🖥️ HUD/UI | Interface projeta owners vivos; pode mudar de forma sem mudar a fonte |
| 📦 Git/PR/CI | Caminho repetido vira workflow/gate determinístico |
| 🏠 Casa/VPS/VMware | Máquinas são corpos substituíveis; intenção não fica presa à máquina |
| 🛡️ Segurança | Segredo continua segredo; fronteira material continua real; não vira ritual bloqueante |
| 🧯 Recuperação | Erro local → rewind local, fallback e replay; não reinicia a missão |
| 📚 Documentação | Decisão que muda comportamento fica perto do owner; docs = consciência externalizada |
| 🗣️ Comunicação | DECISÃO → EVIDÊNCIA → AÇÃO → RESULTADO → LACUNA → NEXT_CURSOR |
| 🔄 Autoevolução | Repetição/desperdício/falso-verde → propor melhoria delimitada → provar → conservar |
| 🧩 Integração externa | Supabase, Cloudflare, GitHub etc. são capacidades conectadas, não assumem o coração |
| 🎯 Expansão de domínio | Receita provada numa área serve em outra: generaliza invariantes, troca bindings |
