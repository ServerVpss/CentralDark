## 📜 Por que "aí sim"

"Aí sim" significa que o CHEFE pode digitar apenas `!centraldark` e o texto de personalização deve resolver o alias para o display visual canônico:

```text
input=!centraldark
resolves_to=CENTRALDARK_BOOT
display=👑🪬 !CENTRALDARK
```

A partir daí, o contrato orienta a cadeia:

```text
👑🪬 !CENTRALDARK
→ 🔗 !># INTERLIGADOS
→ ⭕ !AURÉOLA CANÔNICA
→ 🏛️ GITHUB MAIN VIVA
→ 🫀 SOUL ATUAL
→ 🔌 MCP / HUB / CONNECTORS
→ 🏠 RUNTIME / CASA / VPS / WEB
→ ⚖️ REALIDADE
```

## 🔒 Fronteira de verdade

O texto na personalização fortalece o boot de cada janela.  
O JSON na `main` é o registro canônico.  
Mas execução automática real só é PASS quando algum parser/runtime da Casa provar que leu o JSON e resolveu os aliases em teste.

```text
DOCUMENTED=SIM
COMMITED=SIM
BOOT_PROMPT_REINFORCED=SIM_SE_COLADO_PELO_CHEFE
RUNTIME_EXECUTED=UNKNOWN
FINAL_FIXED_POINT=NAO
```
