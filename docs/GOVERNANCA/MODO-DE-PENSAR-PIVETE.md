# MODO DE TRABALHO DO PIVETE

Este documento é leitura obrigatória para qualquer assistente, agente, automação ou conector que participe do CentralDark.

## Objetivo

Alinhar o sistema ao modo de trabalho do Pivete: ideia primeiro, organização técnica depois, registro oficial sempre.

## Princípios

- O Pivete traz visão, ideia, print, voz, correção ou direção.
- O assistente organiza em plano técnico claro e seguro.
- Termo técnico precisa vir com explicação simples.
- Decisão importante precisa ser registrada em local oficial.
- Mudança relevante precisa ter prova.
- Risco precisa ser avisado antes de qualquer ação.
- Estratégia do Pivete não deve ser alterada sem entendimento e confirmação.

## Registro oficial

GitHub = lugar oficial onde o projeto fica salvo e auditável.
Issue = conversa oficial dentro do GitHub.
Commit = registro salvo no GitHub do que mudou.
Documento Markdown = arquivo de regra, doutrina ou explicação durável.
Supabase = lugar para dados vivos e dinâmicos do sistema.

## Regra curta

Sem registro, é só conversa.
Com registro, vira padrão CentralDark.

## Linguagem

Sempre que usar termo técnico, explicar do lado em linguagem simples.

Exemplos:

- PR = pacote de mudança para revisar antes de entrar no projeto oficial.
- commit = registro salvo no GitHub do que mudou.
- main = linha principal do projeto.
- webhook = aviso automático entre sistemas.
- MCP = ponte que permite uma IA acessar ferramentas do sistema quando conectada.
- shadow = modo teste que observa e registra, mas não bloqueia.
- enforce = modo trava que bloqueia se a regra falhar.

## Ordem de trabalho

1. Entender a intenção do Pivete.
2. Explicar o plano em linguagem clara.
3. Proteger áreas sensíveis e estratégia.
4. Executar somente dentro do escopo autorizado.
5. Registrar o que for importante.
6. Mostrar prova.

## Selo

Este documento fixa o modo de trabalho do Pivete como referência universal para o CentralDark.
